## 零 · 先看清「DSH 风格」到底是什么

不能凭印象。我把 DSH 原生的实际值量出来（从 `document.body` 读 token）：

```
中性色   --dsw-alias-label-primary / label-secondary / label-tertiary / label-quaternary
边框     --dsw-alias-border-l1/l2/l3/l4（越往后越淡）
交互     --dsw-alias-interactive-bg-hover / interactive-bg-active
表面     --dsw-alias-bg-base / bg-layer-1 / bg-layer-2 / bg-layer-3
浮层     --dsw-menu-surface-fill（半透明 + blur）
圆角     --dsw-radius-sm: 8px / md: 12px / lg: 16px
阴影     --dsw-elevation-prominent
```

**DSH 的设计语言（我从截图里量出来的）**：

| 特征 | DSH 的做法 | ArtCraft 现在的做法 |
|---|---|---|
| 控件边框 | **几乎没有边框**，靠底色差异分层 | 到处是 1px 实线边框 |
| 图标 | 少量、必有文字或明确语义 | 25 个纯图标按钮 |
| 浮层 | 半透明磨砂 + 16px 圆角 + 三层阴影 | 导出面板 radius 0 / shadow none |
| 输入框 | 无边框或极淡边框，聚焦才显色 | `2px inset rgb(118,118,118)` 浏览器默认 3D 边框 |
| 层级 | 靠「弱化陪衬」而不是「加强边框」 | 靠边框和阴影堆 |

## 一 · 10 条问题的实测归因

### ① 工程名输入框不像 DSH

**实测**：
```
w=87  h=34  radius=8px
border: 2px inset rgb(118, 118, 118)   ← 浏览器默认 3D 凹陷边框！
padding: 1px 8px
```

**根因**：ArtCraft 关了 Tailwind preflight，`<input>` 完全没被样式重置，
吃到了 UA 默认的 `2px inset`。这就是「看起来像 1998 年的网页」的原因。

**修法**：用 DSH 的真实做法 —— 无边框、透明底、hover 时显示淡底、聚焦时才显示边框。

---

### ② 导出二级菜单「宽度顶格走，导致出框」

**实测**：
```
w=336  x=1576  right=1912
overflowRight = 0        ← 紧贴窗口右边缘，零留白
bg = rgba(0,0,0,0)       ← 透明！
radius = 0px             ← 没圆角
shadow = none            ← 没阴影
```

**根因有两层**：
1. `mr-4` 那个 margin 没生效（Radix popper 的 style 覆盖了它）
2. 更严重：**这个 div 只是外层定位容器，没有浮层外观** —— 真正的 PopoverContent 是它的子元素，但子元素尺寸被父容器吃了。

所以主人看到的是「一块透明的、紧贴边缘的、没有圆角阴影的白板」。

**修法**：浮层用 DSH 的真实浮层规格 ——
```
background: var(--dsw-menu-surface-fill)   半透明
backdrop-filter: blur(40px) saturate(150%)
border-radius: 16px
box-shadow: var(--dsw-elevation-prominent)
margin: 8px（四周都留）
```

---

### ③ 素材面板底部滑块「莫名其妙的」

**实测**：
```
scrollWidth = 280   clientWidth = 264
overflowX = auto
溢出 16px
```

**根因**：面板可用宽 264，但内容按 280 排版 —— 多出的 16px 是**滚动条自身宽度**被算进了内容。
于是出现「内容只差一点点、却出了个横向滑块」的难看状态。

**主人的要求（二选一）**：
- A：按可用宽度自适应双列
- B：就一列

**我的判断**：素材面板很窄（264px），双列每张卡只有 126px —— 缩略图太小看不清。
而且主人图上显示的是**单列大卡**（拖拽区那种）。

⇒ **选 B：一列**。但要保证「一列永不溢出」：
```
宽度用 100% 而不是固定像素
padding 用 box-sizing: border-box 算进去
溢出时靠 min-width:0 让子元素收缩，而不是撑破
```

---

### ④ 轨道区居然能拖 DSH 侧栏

**实测（这是最隐蔽的一条）**：
```
ArtCraft 时间轴容器：x=280 → 1905（铺满整个中栏宽度）
DSH 拖拽手柄 Dc7zOa_widthHandle：x=612 宽 10、全高 838、z-index 0
```

**根因**：DSH 的拖拽手柄 `z-index: 0`，而 ArtCraft 时间轴区域**盖在它上面**
（DOM 上 ArtCraft 后插入）。但 DSH 的手柄仍然能接收 mousedown ——
因为它在 `x=612` 那一竖条上没有任何竞争者。

⇒ 主人在轨道区左右拖动时，命中的是 **DSH 的手柄**，不是轨道。
看起来像「轨道能拖动」，实际是把 DSH 侧栏拖窄了。

**修法**：这个**不能靠 CSS 解决**（会破坏 DSH 自己的功能）。
正确的做法是：**把 ArtCraft 的内容限制在它该在的容器里**，
不要跨过 DSH 的 panel 边界。

但更实际的问题是：为什么 ArtCraft 时间轴会铺到 x=1905？
它应该在 `.ac-scope` 内部才对。**这一条要先查清再动手。**

### ⑤ 音轨拖不回音频1，还凭空多出一条「音频」

**当前实测轨道**：
```
overlay: 视频 2(0) / 字幕(0)
main:    视频 1
audio:   音频 1(0) / 音频 2(0)
```

主人图里显示的是：音频轨变成了 `音频 / 音频 1 / 音频 2` —— **多了一条「音频」**。

**归因（两个独立缺陷）**：

1. **拖不回**：`resolveTrackPlacement` 的 `explicit` 模式在目标轨已有元素时，
   可能因为「时间区间重叠」拒绝，并静默失败（不回退、不报错）。
2. **幽灵轨**：拖放时如果 `trackId` 解析失败，`insertElement` 走了 `auto` 分支，
   而 `auto + firstAvailable` 装不下就会**新建一条音频轨** —— 名字用
   `DEFAULT_TRACK_NAMES.audio` = `"音频"`。

这正好解释了「凭空出现一个（音频）轨道」。

**修法**：
- 拖放的目标轨 id 必须严格校验，解析失败要**报错**而不是 fallback
- `firstAvailable` 在音频轨全满时**不应该新建轨**（用户的四轨布局是固定的）

### ⑦ 图标太多，功能全靠背

**实测**：时间轴工具栏 **17 个按钮，15 个纯图标无文字**。

```
分割片段 / 向左分割 / 向右分割 / 提取音频 / 复制片段 /
定格帧 / 删除片段 / 添加书签 / 关键帧 / 切换场景 /
自动吸附 / 波纹编辑 / 缩小 / 放大 / 增高轨道 / 减矮轨道
```

**这些都是「要看 tooltip 才知道是什么」的按钮。**

**DSH 的做法**：主操作有文字，次操作收进溢出菜单。

**修法**：分三档
```
常驻（有文字）：  分割 / 删除          ← 最高频
图标（有 tooltip）：复制 / 提取音频      ← 次高频，图标本身够直观
收进菜单（···）：  向左/右分割 / 定格帧 / 书签 / 关键帧 / 波纹编辑 / 吸附
```

---

### ⑧ @卡片不跟随文字，tag 菜单白字

主人原话：「这个卡片的框不是跟随文字了」「文字全是白的，不点上去根本不知道是什么字」

**根因（两个）**：
1. 卡片的 `left` 是按**字符数估算**算出来的，不是按真实文字宽度 ⇒ 文字一变就错位
2. tag 菜单用了 `--dsw-alias-label-primary-foreground`（白/黑随主题翻转），
   但它的背景不是品牌色 ⇒ 白底白字

**修法**：
- 卡片定位改用 `Range.getBoundingClientRect()` 拿**真实像素位置**
- tag 菜单文字用 `--dsw-alias-label-primary`，不用 foreground

## 四 · 已排除的错误做法（留痕，防止后面又提）

```
✗ 给 DSH 的拖拽手柄加 pointer-events:none

✗ 把工具栏图标全换成文字
  → 17 个文字按钮会撑爆 957px 的工具栏（实测 375px 时就已需要横向滚动）。

✗ 用暗色主题做预览
```
