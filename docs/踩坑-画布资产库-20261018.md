# 画布式资产库的六个静默失效

### 6.10 画布式资产库（2026-10-18，M2 画布房间）

```
★ 需求原文（主人）：
   「现在的视频工作台部分是不是空白太多？弄成画布怎么样？」
   「图片不能打开，不能保存，不知道对应的是哪个的产物」
   「生成后直接弹到画布里面？」

❌ 产物标签判不出来（标成「产物」而不是「二采/高清重绘/SeedVR2」）

   ★★ 2026-10-19 更正（复核员 e31d7b8a 指出，我复跑确认，原文有误）：
      原文写「SaveImage 的 filename_prefix 被作者改成了 zzz-renamed-220/186/174，
      只带节点号不带语义」——【这是错的】。
      实读 workflows/krea2-full.json 得到：
        node 220 → Krea2-2ST-20261018
        node 186 → Krea2-USD-20261018
        node 174 → Krea2-SVR-20261018
      prefix 都带语义。
      ⇒ 当时判不出标签，真正原因不是「文件名无语义」，而是：
        · 那时前端只用 o.url 里的 filename 做匹配，没读 type 字段；
        · 而 202(PreviewImage) 落成 ComfyUI_temp_*，另外三个前缀我认错了。
      保留本条的真正结论：**来源的权威是 bind.outputs 的 nodeId 映射**，
      理由改为「文件名可被人随手改，nodeId 是结构标识不会变」。
✅ 唯一权威是 bind.json 的 outputs 映射：
     { image:202, imageTwoPass:220, imageUsd:186, imageSeedvr:174 }
   但 /comfy-bridge/modes 不返回 outputs，且硬约束是「不改 bridge」
   ⇒ M2 自己的 host 侧开 /comfy-assets/roles，只读扫一遍 workflows/*.bind.json
     反转成 nodeId → roleKey 给前端。桥一行没动，节点号也不写进代码。
   前端三层判据：① nodeId→角色（权威） ② 文件名 ③ 落地「产物」+ 印节点号

❌ 下载点了不是下载（会导航走 / 403）
   实测（node fetch 直测 8188）：
     GET /api/view?...                          → 200
     GET 同上 + Origin: http://127.0.0.1:19499   → 403
     OPTIONS 同上（preflight）                    → 403
   ComfyUI 的 aiohttp 对带 Origin 的跨源请求一律 403。
   <img> 是 no-cors 不带 Origin ⇒ 图能看；<a download> 跨源时 download 被忽略。
✅ M2 host 侧开 /comfy-assets/view 做同源代理（不带 Origin 去请求上游），
   download=1 时加 Content-Disposition: attachment。
   实测：代理与直连 sha256 完全一致，浏览器点击后文件真的落盘。

❌ lightbox 被 DSH 侧栏/顶栏盖住
   根因：它不是 z-index 不够，而是 conversation.view 的祖先带 transform，
        形成新的 stacking context，里面的 z-index:99999 只在该 context 内排序。
✅ createPortal 到 document.body 才真正浮在全页之上。
   遮罩不透明度 0.84 → 0.92 + backdrop-filter: blur(8px)，背景才彻底压住。

❌ 滚轮缩放完全没反应（拖平移却正常）
   根因：wheel 监听用 useEffect([onWheel]) 挂，而 onWheel 是 useCallback([],…)
        恒稳定。空状态时 wrapRef.current 还是 null（空态走 EmptyCanvas 提前
        return，那个 div 没挂），effect 直接 return 掉了；等产物到了 div 才
        出现，但依赖没变 ⇒ effect 不重跑 ⇒ 监听永远没挂上。
   判据：派发 WheelEvent 后 ev.defaultPrevented 恒为 false（有监听会 true）。
✅ 依赖加上 cards.length，让「第一张产物到来」时重新挂一次。
   实测：scale 从 1.616 → 2.6117，围绕指针缩放。

❌ 加产物时把用户拖好的卡片全弹回原位
   根因：每轮轮询 setJob 的都是【整个重建的新数组】，若把数组当身份，
        每次都被当成「一批全新产物」而重新排布。
✅ 按 nodeId+filename 做增量合并（assetKeysRef 去重），已存在的不动。

❌ 4 张卡被容器裁掉 / 缩到 47% 看不清标注
   根因：3 列 × CARD_H=250 在 346px 高的画布里必然溢出。
✅ 改 4 列 × CARD_W=240/CARD_H=232，一行排开；fit 的缩放下限设 0.45，
   宁可让第二行探出也不把「一采/二采」标签缩成蚂蚁。

★ 画布方案：手写 CSS transform（pan + zoom + 卡片拖动），零依赖。
  不引 tldraw 的理由：5.5.2 未压缩 15.2 MB，且必须注入它自己的 CSS，
  而 build.mjs 打的是单个 IIFE、没有 CSS 通道，塞 <style> 会污染 DSH 全局。
  不引 react-zoom-pan-pinch 的理由：只给整体 pan+zoom，卡片各自拖动仍要写，
  省不到 60 行，却多一次装包与 react 版本匹配风险。

★ 验收脚本：packages/dsh-comfy-workbench-tab/verify-canvas.mjs
   实测 20 通过 / 0 失败。它不测浏览器交互（lightbox/平移/缩放/自动弹出），
   那几条的证据是 docs/预览/_shots/canvas-*.png + console 读数。
```
