# 踩坑 · 批量改代码的四个陷阱（2026-10-23）

> 本轮做 D2（去掉 `D:/主工作区/...` 绝对路径），用脚本批量替换 16 处。
> 过程中连踩四个坑，全部记录。

---

## 坑 1 · 漏 import 的标识符，语法检查抓不到

**症状**：

```js
const MOD = pathToFileURL(path.resolve(HERE, "lib", "asset-scan.js")).href;
```

`node --check` **通过**，真跑报：

```
ReferenceError: pathToFileURL is not defined
```

**根因**：拼 `import { fileURLToPath } from "node:url"` 时没带 `pathToFileURL`。
未声明标识符在语法层面完全合法，只有执行到那一行才抛。

**判据**：

| 手段 | 能不能抓到 |
|---|---|
| `node --check` | ❌ 只查语法 |
| 静态 grep「有没有 import」 | ❌ 我 grep 了 `fileURLToPath` 就以为够了 |
| **真跑** | ✅ 立刻暴露 |
| `tools/check-undeclared.mjs` | ✅ acorn 词法作用域分析能抓到 |

⇒ **批量改代码后必须真跑**，而且先跑 `check-undeclared.mjs`（本项目现成的工具）。

**修**：`import { fileURLToPath, pathToFileURL } from "node:url";`
两处都是：`verify-character-bridge.mjs`、`verify-role-contract.mjs`。

## 坑 2 · 重复 import

脚本检测到「没有 `path` import」就插一条，但原文件**可能已经有**
（只是不在我 grep 的那一行）⇒ `path` 被 import 两次 ⇒ 语法错误。

**修**：插 import 前查**整个文件**，不是查某一行。

---

## 坑 3 · 插在语句中间

`const HERE = ...` 插在了 L2（第一条 import 之后），而 `path` 的 import 在 L37。
ESM 会提升 import 所以能跑，但可读性差、后续编辑易错。

**修**：插入位置选「所有 import 之后的第一行」。

---

## 坑 4 · 一套锚点只覆盖一种写法

第一次只处理了 `const X = "D:/..."`，漏了 `file:///D:/...`（三个斜杠的 URL 形式）。

**修**：替换前先列出**全部形态**再写规则。

> ★ 这条在 D3 去敏（`C:/Users/...`）时已经踩过一次，
> 这次是同一个坑的变种（漏了 `file:///` 前缀）。
> **同一个认知错误会在不同字面量上重复出现。**

---

## 附带修掉的一个设计问题

`verify-no-english.mjs` 缺样本文件时 `exit(2)` ⇒ 在 `verify-all` 里永远显示失败，
而真实原因只是「还没在浏览器里导出文本」。

**改成跳过**（exit 0）并给出三个可执行步骤：

```
– 跳过：没有导出样本，无法检测漏翻
   让它真的跑起来：
     ① 打开剪辑台，浏览器控制台执行
        copy(document.querySelector('.ac-scope').innerText)
     ② 存成 <repo>/.state/timeline-text.txt
     ③ 重跑本脚本
通过 0 / 0（跳过）
```

★ 跳过 ≠ 失败：跳过=今天不适用，失败=真检出漏翻。
混在一起会让「没准备样本」显示成「功能坏了」。

### 顺带去掉的双根逻辑

`verify-all.mjs` 原来有：

```js
const HERE  = 'D:/主工作区/DSH视频工作台/packages';
const HERE2 = 'D:/主工作区/DSH视频工作站/packages';
function rootOf(dir) {
  return fs.existsSync(p2) && !fs.existsSync(p1) ? HERE2 : HERE;
}
```

`HERE2` 指向**另一个仓库**。而 D1 已把 `dsh-editor` 并进本仓库，
两边现在都有 `dsh-editor` —— 双根逻辑已经过时，靠 `existsSync` 碰巧走对。

改成单根（`path.dirname(fileURLToPath(import.meta.url))`），
且 `rootOf` 返回 `null` 时明确报「包目录不存在：xxx」而不是拼出 `"null/xxx"`。
