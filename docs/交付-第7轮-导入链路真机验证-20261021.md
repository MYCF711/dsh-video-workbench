## 一 · 为什么前几轮误判「素材面板为空」

```

实际情况：  ArtCraft 的素材面板【不读 ComfyUI 资产库】，
```

资产库根本不空，是我看错了地方。

## 三 · 发现的两个真缺陷

### 缺陷 1：音频轨叫 `Audio track`

```
修前：导入视频 → 音轨分离 → 但那条轨的名字是 "Audio track"
根因：lib/timeline/tracks.ts 的 DEFAULT_TRACK_NAMES 全是英文：
      video: "Video track"  text: "Text track"  audio: "Audio track" …
      我前几轮改的中文名只作用在 dsh-projection 输出的【固定 5 条轨道】，
      而【自动新建的轨道】走的是这套默认名。
修后：视频 / 字幕 / 音频 / 贴纸 / 特效
```

### 缺陷 2：★★ 导入后「视频 2」和「字幕」凭空消失

**这是本轮最重要的发现。**

```
修前（我复现了三次）：
  导入前 overlay = ["视频 2", "字幕"]
  导入后 overlay = []            ← 两条都消失
  audio 从 ["音频 1","音频 2"] → 1 条

根因：lib/core/index.ts 有一个 prune reactor：
    overlay: tracks.overlay.filter((track) => track.elements.length > 0),
    audio:   tracks.audio.filter((track) => track.elements.length > 0),
  它每次命令执行后把【元素为空的轨道】删掉。

  ⇒ 这是【设计冲突】，不是 bug：
    · ArtCraft 的立场：空轨没用，别占地方（对通用剪辑软件是对的）
    · 主人的立场：默认给我五条，我要往第二条视频轨拖东西
    两者都对 ⇒ 需要的是「哪些轨道允许为空」的显式白名单。
```

**修法**：加 `PINNED_TRACK_IDS` 白名单，四条固定轨道 id 永远不参与 prune。

**实测修复后**：

```
导入后：视频2(0) / 字幕(0) / 视频 1(1视频) / 音频1(1音频) / 音频2(0)
                      ↑ 三条空轨全部保留
```

## 四 · 抓根因的方法（值得记）

我用 `updateTracks` 打补丁抓调用栈，一次就定位：

```
updateTracks 被调了三次：
① overlay=2, audio=2  ← InsertElementCommand（正常插入）
② overlay=0, audio=0  ← runReactors（★ 这里清空的）
③ overlay=0, audio=1  ← InsertElementCommand（音轨分离）
```

**判据**：一个「数据凭空消失」的问题，最快的定位方式是 hook 住写入点抓栈，
而不是读源码猜。我前面读了三处源码都没找到，hook 一次就出来了。

## 七 · 本轮的方法论教训

### 「环境不具备」这个结论，要先证伪

我连续三轮说「需开 ComfyUI 才能验」。
实际只要**换一条路**（`input[type=file]` 而不是拖放）就能验，而且 ComfyUI 关着也不影响上传。

⇒ 当我说「做不了，因为 X」时，先问：**X 真的挡死了所有路径吗？**
  这次 X（ComfyUI 关闭）只挡死了「读回生成产物」，没挡死「上传本地文件」。

### 「设计冲突」与「bug」要分开处理

缺陷 2 如果当成 bug 去修（比如让 prune 永远保留所有轨道），
会让通用场景下攒一堆没用的空轨。
正确的处理是**加一个显式的白名单**，把「哪些允许为空」变成一个有意的决定。

⇒ 判据：修之前先问「另一方这样设计，在它的语境下对不对？」
  对 ⇒ 不是 bug，是需求差异 ⇒ 加法（白名单/开关），不是删法。
