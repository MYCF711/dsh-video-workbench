## 二 · 设想（R1 发散 —— 好的坏的都写，不取舍）

### 2.1 提示词区

```
a. 提示词框固定高度（如 min-height 88px），不随内容跳动
b. 提示词框上方加一行「本镜配方」摘要：多参 H3 · 16:9 · 5秒
   ⇒ 让用户知道「这句话会被什么模型怎么理解」
c. chip 嵌在文本流里（已经是了），但补齐三要素
d. 提示词框右下角放字符计数（H3 有长度限制吗？未验证）
e. 提示词框上方放「参考素材」横向缩略图条 —— 与 chip 重复
   ⇒ 主人说过「去掉 RefStrip 独立小卡片，引用只在正文显示」
   ⇒ 这个设想与主人明确要求冲突，记为否决
f. 用 contenteditable 替代 textarea —— 技术上能真内联，但要自己实现
   光标 / 选中 / 撤销 / 输入法，风险高
g. 保持 textarea + 覆盖层（现状），只把覆盖层做对
```

### 2.2 chip 三要素

```
a. 预览图：图片直接显示；视频抽首帧；音频显示波形或图标
   ★ 时间轴那边已经实现了视频抽首帧（mediaAssets.js probeMeta）
     但那在 dsh-artcraft-tab 包里，工作台这边要独立实现
b. 名字：优先 displayName（用户改过的名），回退 name
   ★ AGENTS §6.16 提过这个坑：「应把文件名同步修改」
c. 用途 tag：小胶囊，点击弹下拉切换
d. tag 显示成中文（角色外观 / 首帧 / 动作 …），不显示 subject.character
e. chip 高度不超过 20px，与正文行高协调
f. chip 太长时省略号，hover 显示全名
```

### 2.3 参数行

```
a. 主次：生成按钮用 --dsw-alias-button-primary-fill（已有）
   其余全部 ghost 风格（无边框、hover 才显底）

d. 「资产库 871」的数字改成更小的字体，作为角标

### 2.4 空态

   「还没有产物」+ 两个入口按钮：`打 @ 引用资产` / `直接生成`

## 三 · R2 批判（逐条问「这条真的该做吗」）

### 3.1 被否掉的

```
✗ 2.1e 参考素材横向缩略图条
   理由：与主人明确要求「引用只在正文显示」冲突。
   ★ 记入 §五 否决清单，永不重提。

✗ 2.1f contenteditable 替代 textarea
   理由：要自己实现光标 / 选中 / 撤销 / 输入法 / 粘贴过滤，
        任何一个做错都会让「打字」这件最基本的事出问题。
   判据：AGENTS §6.20 —— WorkbenchInner 加 useState 都能让整页崩，
        这种程度的不确定性不该用在最核心的输入框上。

✗ 2.1d 字符计数
   理由：H3 是否真有长度限制未验证。不做未验证的功能。

✗ 2.5d 拖拽资产到文件夹
   理由：本轮首要目标是「摆对位置 + 补缺口」。
        拖拽是增强，不是缺口。留到以后。

✗ 2.5c 文件夹重命名 / 删除
   理由：同 2.5d。新建是缺口（没有入口就建不了），改名删是增强。
```

### 3.2 被修正的

```
△ 2.2a 视频抽首帧
   原设想：在工作台这边再实现一遍
   修正：dsh-artcraft-tab/src/mediaAssets.js 的 probeMeta 已经写好了，
        逻辑相同。但两个包不能互相 import（各自独立打包）。
        ⇒ 抽成公共模块？还是复制？
        ★ 判据：这段逻辑约 60 行，依赖浏览器 API，无第三方依赖。
          复制的代价：将来改一处漏一处（本项目已有先例：tracks.overlay 踩了两次）。
          ⇒ 放进 dsh-comfy-workbench-tab/src/media-probe.mjs，
            由两个包各自的 build 内联。但 artcraft-tab 的 build.mjs 不处理这个...
        ⇒ **本轮先只做工作台这边的 chip 预览**，
          artcraft-tab 那边已经在用同一套逻辑且验证过，不动。
          记录：将来如果要合并，抽到 packages/_shared/。

△ 2.3b 参数分组左右
   原设想：左边参数右边动作
   修正：DSH 原生输入区的布局是「＋ 附件 | 输入框 | 发送」，
        参数在输入框下面一行、靠左。
        ⇒ 保持一行、靠左，但把「生成」放最右（与发送按钮位置对齐）

△ 2.4d 空态网格背景
   原设想：加网格
   修正：AGENTS §6.10 说画布已经有 pan/zoom。
        加网格要改 canvas 容器，风险 vs 收益不划算。
        ⇒ 只改文案 + 图标，不动结构。
```

### 3.3 批判发现的**新问题**（原本没想到）

```
★★ 新-1 · sessionStorage 会持久化「用户不该看到的内容」
   实测：提示词框里残留了 "subject_definitions:\n<Subject 1> is the..."
   根因：我把内部格式写进过 prompt 字段，被持久化。
   ⇒ 该加一道防御：loadPersisted 时如果发现 prompt 里有内部标记，清掉。
   判据：AGENTS §6.24「存档损坏要隔离，不能静默清零」同类 ——
        宁可清掉并告知，也不要带着脏数据继续跑。

★★ 新-2 · 提示词框上方那条波浪线来源不明
   截图能看到，但不知道是什么。
   ⇒ 必须先查明再动手改。判据：「先看实际值，再猜代码」。
   如果它是 chip 高亮层的边界，那就说明高亮层尺寸算错了。
```

```
┌──────────────────────────────────┐
