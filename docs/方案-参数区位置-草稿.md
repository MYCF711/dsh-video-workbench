## 一 · 现在到底浪费在哪

```
纵向：
  状态条   39px   ● ComfyUI 已连接 · v0.40.0 · 9430 MiB free
  参数条   33px   ▾多参H3★  ▾16:9  ▾5秒  ▾10步          留空随机 [生成]
  开关行   30px   ○ 武打模式
  ─────────────
  合计    102px   ← 参数区吃掉的高度

横向：
  grid 列分配    内容需要    倍数
  462px          60px       7.7×
  330px          24px      13.8×
  297px          24px      12.4×
  297px          31px       9.6×
  ──────────────────────────────
  1554px        307px       5.1×
```

**核心矛盾**：grid 的 `minmax(0, 1.4fr)` 把列按比例铺满，
但控件是 `width:auto` 收缩的 ⇒ 列宽 ≠ 控件宽 ⇒ 右侧全是死空白。

## 方案 A · 参数收进提示词框底部（ChatGPT / Claude 式）

```
┌────────────────────────────────────────────────────────────────┐
│ ● ComfyUI 已连接 · v0.40.0 · 9430 MiB free                     │ 34px
├────────────────────────────────────────────────────────────────┤
│                                                                │
│                     成果展示区（占大头）                          │
│                                                                │
│                                                                │
├────────────────────────────────────────────────────────────────┤
│ ┌────────────────────────────────────────────────────────────┐ │
│ │ 提示词                                                      │ │
│ │                                                            │ │
│ └────────────────────────────────────────────────────────────┘ │
│  ▾多参H3★  ▾16:9  ▾5秒  ▾10步   ○武打  留空随机        [生成]   │ 32px
└────────────────────────────────────────────────────────────────┘
```

**省下**：102px → 66px（状态条 34 + 底部条 32），净省 **36px**
**横向**：底部条内自然排列，控件按内容宽，无死空白
**复杂度**：中 —— 要调 flex 顺序（成果区提前、提示词+参数收进底部容器）
**风险**：提示词在下方，与主人「核心区域留给提示词」略有出入，但视觉上
提示词仍是大块，且更符合「输入完就发送」的直觉

## 方案 B · 状态条与参数条合并成一行

```
┌────────────────────────────────────────────────────────────────┐
│ ● 已连接 · 9430 MiB  │ ▾多参H3★  ▾16:9  ▾5秒  ▾10步  ○武打  [生成] │ 36px
├────────────────────────────────────────────────────────────────┤
│ 提示词                                                          │
│                                                                │
├────────────────────────────────────────────────────────────────┤
│                     成果展示区                                  │
└────────────────────────────────────────────────────────────────┘
```

**省下**：102px → 36px，净省 **66px**（最省）
**横向**：一行内左状态、右参数，中间留白但被两端内容「夹住」不显空
**复杂度**：低 —— 只改容器合并
**风险**：窄窗口下会挤（需要 <1100px 时状态文字缩成「● 已连接」）

```
┌────────────────────────────────────────────────────────────────┐
│ ● ComfyUI 已连接 · v0.40.0 · 9430 MiB free                     │ 39px

│                                          ▾多参H3★ ▾16:9 ▾5秒 [生成] │ 33px
├────────────────────────────────────────────────────────────────┤
│ 提示词                                                          │
├────────────────────────────────────────────────────────────────┤
│                     成果展示区                                  │
└────────────────────────────────────────────────────────────────┘
```

**省下**：高度不变（102px），但**横向不再有死空白**（参数靠右紧凑）
**复杂度**：最低 —— 只把 `grid` 改成 `flex` + `justify-content: flex-end`
**风险**：高度一点没省，主人说的「占据最好的部位」没解决

## 方案 D · 参数折叠成一行摘要 + 点击展开

```
┌────────────────────────────────────────────────────────────────┐
│ ● ComfyUI 已连接 · 9430 MiB          H3 · 16:9 · 5秒 · 10步 ⚙  │ 34px
├────────────────────────────────────────────────────────────────┤
│ 提示词                                                          │
│                                                                │
│                                                                │
├────────────────────────────────────────────────────────────────┤
│                     成果展示区                                  │
└────────────────────────────────────────────────────────────────┘

点 ⚙ 后：
│ ● ComfyUI 已连接 · 9430 MiB          H3 · 16:9 · 5秒 · 10步 ⚙  │
│ ▾多参H3★  ▾16:9  ▾5秒  ▾10步  ○武打  留空随机        [生成]     │ ← 临时展开
```

**省下**：102px → 34px，净省 **68px**（最省）
**横向**：摘要是一行文字，利用率高
**复杂度**：中高 —— 要加展开/收起状态 + 点外面关闭
**风险**：**参数被藏起来，改一次要两步**。主人之前批评过「脱裤子放屁」，
        这个方案可能被认为更绕

## 我的判断

| 方案 | 省高 | 复杂度 | 有无「多一步」 | 推荐度 |
|---|---|---|---|---|
| A 底部条 | 36px | 中 | 无 | ★★★★ |
| B 合并一行 | 66px | 低 | 无 | ★★★★★ |
| C 靠右 | 0px | 最低 | 无 | ★★ |
| D 折叠 | 68px | 中高 | **有** | ★★ |

**我倾向 B**：省最多（66px）、改最少、没有「多一步」的问题。
但它有个隐患 —— 窄窗口下状态文字和参数会打架，需要断点处理。

**A 更稳**：符合主流产品（ChatGPT）的肌肉记忆，任何宽度都不挤。
