### 0.2 三个问题（实测）

```
① 全英文
   时间轴 tab 里【一行中文都没有】。
   而主人在视频工作台那边已经全部中文化了 ⇒ 两个 tab 语言不一致。

② 设计语言与 DSH 有距离
   ArtCraft 是 Tailwind + shadcn 风格：
     · 圆角偏大（rounded-sm / rounded-md 混用）
     · 阴影较重（shadow-lg）
     · 按钮高度 28~32px，DSH 原生约 22~28px
   虽然已经做了 .ac-scope 作用域 + --st-* 主题变量对齐，
   但「控件尺寸 / 圆角 / 阴影」这三样没对齐。

③ 文案硬编码，没有 i18n 层
   实测：ArtCraft 源码里 grep i18n / useTranslation / locale/
   ⇒ 零命中。63 条英文文案全部硬编码在 .tsx 里。
```

### 0.3 已知的约束（不能违反）

```
· 不能改 ArtCraft 的【行为】，只能改【文案与样式】
· 8.5MB 内联 payload，每次改都要重跑三步构建（约 3 分钟）
· 改 .tsx 后必须 build-dsh-proof.mjs → build.mjs → 重启 → 刷新
· theme-light / theme-gray 两套主题都要验
· .ac-scope 作用域不能破（破了会污染整个 DSH）
```

## 二 · 设想（R1 发散）

### 2.1 中文化

```
a. 逐条改 .tsx 里的硬编码文案
   63 条，改完要重新构建 8.5MB payload
b. 在 evalArtCraftOnce 之后做一层【运行时 DOM 翻译】
   用 MutationObserver 监听，把英文节点替换成中文
c. 给 ArtCraft 注入一个全局 t() 函数，改所有 .tsx 调用 t()
   ⇒ 要改 63 处调用点，且要找全（漏一个就混语言）
d. 只翻译【用户会看到的 40 条】，属性面板那些深层的先不动
e. 用 CSS content 替换 —— 做不到（DOM 里有文字节点）
```

### 2.2 尺寸对齐

```
a. 改 Tailwind 的 spacing 配置（tailwind.config）让 h-8 变成 28px
   ⇒ 影响面不可控，可能把布局搞坏
b. 给 .ac-scope 加一层 CSS 覆盖，把关键选择器的高度/圆角/阴影改掉
   ⇒ 精准，但要先量出哪些选择器
c. 改 ArtCraft 的 base.css 里的 CSS 变量（如果有 --radius 之类）
d. 什么都不改，只做中文化
   ⇒ 主人说过「功能和 ui 都很好才算完成」，不能只做一半
```

### 2.3 颜色与主题

```
a. 已经把 --st-* 对齐了（§八已验）
b. 但 DSH 的 --dsw-* 和 ArtCraft 的 --st-* 是两套
   ⇒ 是否要让 --st-* 从 --dsw-* 派生？这样换主题自动跟随
c. 现状是两套独立，靠 ac-scope.theme-* 类切换
   ⇒ 已经能跟随（实测浅色/暗色都验过），不必再动
```

## 三 · R2 批判

### 3.1 被否掉的

```
✗ 2.1c 注入全局 t() 改 63 处调用点
   理由：要找全所有调用点，漏一个就混语言。
        而且改动量大、风险高、收益与 2.1a 相同。
        判据：AGENTS §6.38「修一半比没修更隐蔽」——
              混语言比全英文更糟。

✗ 2.1b 运行时 DOM 翻译（MutationObserver）
   理由：① 性能风险（时间轴频繁重绘，每次都扫 DOM）
        ② 会把用户输入的内容也翻译（比如提示词里的英文）
        ③ 无法处理 placeholder / title / aria-label
        ④ 调试困难：源码是英文，界面是中文，对不上
   ★ 这条特别值得否掉：它看起来「不用改源码很省事」，
     但把问题从编译期推到运行期，是最难维护的那种省事。

✗ 2.2a 改 Tailwind spacing 配置
   理由：影响面不可控。h-8 可能在 50 个地方被用，
        改一处配置全局位移，且无法预测。

✗ 2.4 只做中文化，不做尺寸对齐
   理由：主人明确说过「ui 需要和 dsh 的默认 ui 无违和感」。
        只改语言不改尺寸，违和感仍在。
```

### 3.2 被修正的

```
△ 2.1d 「只翻译用户会看到的 40 条」
   修正：先实测【哪些文案真的会出现】，而不是猜。
        方法：点遍所有面板，记录 DOM 里出现的英文。
        ⇒ 结果决定范围，不是先定范围再找文案。

△ 2.2b 「加 CSS 覆盖」
   修正：要先量出目标值。
        DSH 原生：按钮高 22~28px、圆角 6~8px、阴影极淡（0 0 0 0.5px）
        ArtCraft：按钮高 28~32px、圆角 4~8px、shadow-lg
        ⇒ 只改【差得多的那几项】，不是全改。
```

### 3.3 批判发现的新问题

```
★★ 新-1 · 改 .tsx 的成本很高（每次 3 分钟三步构建）
   ⇒ 必须【一次性把能改的都改完】，不能改一条构建一次。
     做法：先把所有文案列成清单，一次性替换，构建一次验证。

★★ 新-2 · 怎么验证「没有漏翻」
   人工看截图不可靠（63 条看不全）。
   ⇒ 写一个脚本：进每个面板，收集 DOM 里的英文单词，
     对照允许清单（品牌名 / 专有名词）。有意外就是漏了。

★ 新-3 · 属性面板里有大量专业术语
   （Bezier curve editor / Checkerboard / Frame rate / …）
   ⇒ 这些是「用户点开某个元素才会看到」的深层面板。
     第一轮只做【默认可见的界面】，深层面板记入待办。
     判据：先让主路径全中文，深层面板单独一轮。
```

## 六 · 定稿

### 6.1 中文化清单（主路径，实测可见）

```
顶栏工具条：
  Export            → 导出
  Assets            → 素材
  Browse            → 浏览
  Import            → 导入

空态：
  Drag and drop videos, photos, and audio files here
                    → 把视频、图片、音频拖到这里
  It's empty here   → 这里是空的
  Click an element on the timeline to edit its properties
                    → 点时间轴上的片段，就能改它的属性

画布控制：
  Fit               → 适应

导出对话框：
  Export project    → 导出工程
  Export finished with errors → 导出完成，但有错误
  Saved to disk     → 已保存到磁盘
  Library upload failed → 上传到素材库失败
  Close             → 关闭
  Format            → 格式
  Quality           → 质量
  Audio             → 音频
  Include audio in export → 导出时包含音频
  Destination       → 保存位置
  Save to disk      → 保存到磁盘
  Save to my media library → 保存到我的素材库

菜单（右键 / 文件）：
  Change pitch      → 变调
  Clear all saved sounds? → 清空所有已保存的声音？
  Delete Scenes     → 删除场景
  Go back           → 返回
  Finish            → 完成
  Export failed     → 导出失败
```

### 6.2 尺寸对齐目标（实测 DSH 原生值）

```
DSH 原生（AGENTS §6.8 实测）：
  dock 里的 token pill：高 22px / 字号 12px / 行高 20px / padding "1px 8px" / 圆角 999

DSH 原生按钮（本轮实测，见 §八 证据）：
  待补 —— 必须先量，不能猜
```

★ **本项不写死数值，先量后改。** 这是从 §6.27 学到的：
「先看实际值，再猜代码逻辑」。

### 6.3 执行顺序

```
① 量 DSH 原生控件的实际尺寸（顶栏按钮 / 主按钮）
② 列 ArtCraft 现有尺寸
③ 一次性改所有文案 + 只改差得多的尺寸项
④ 三步构建 + 重启 + 刷新
⑤ 跑「漏翻检测」脚本
⑥ 两套主题各截一张图
```
