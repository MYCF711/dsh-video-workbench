### 2.1b ★ 浅色主题修复（主人：「改到浅色就原形毕露，很脏的画面」）

**根因（实测，是本轮第二严重的发现）**

```
ArtCraft 的 CSS 里，shadcn 那 16 个变量【只定义了 1 次】，而且只给暗色值：
  --background: 225 10% 8%    --secondary: 240 4% 9%
  --accent: 240 4% 9%         --popover: 240 11% 7%   ...
而它的 .theme-light 类【只改了 scrollbar-color 一行】，根本没重定义这些变量。
⇒ 切浅色主题时：底色变白（--st-bg 派生到 #fff），
  但所有按钮/下拉/选中块仍是暗色值 rgb(22,22,24)
⇒ 白底上一堆黑块，就是主人说的「很脏」
```

**修法**（`dsh-native.css.js` ③b / ③c / ④b 三节）

```
· 补齐 16 个 shadcn 变量的【暗色与浅色两套】
  ★ 浅色值全部取自 DSH 实测：底色 #fff / 文字 #0f1115 / 次要 #61666b
  ★ secondary/accent 用 210 20% 96% 而不是纯白 —— DSH 浅色下 bg-layer-1/2/3
    都是 #fff，若也用 #fff，按钮与底完全分不出
· 补齐 bg-ui-* 系列（导出对话框容器就是 bg-ui-controls）
  ★ 这一族原来只读 --st-*，而 --st-controls 在浅色下等于 #fff
  ⇒ 改成「bg-base + 0.5px 描边 + elevation-panel 阴影」，
    因为 DSH 浅色下的层级本来就靠描边撑，不靠底色差
· 滚动条也跟主题走
  ★ 实测浅色下时间轴底部有一条粗黑带，是 scrollbar-color: rgb(44,44,47)
  ★ token 坑：--dsw-alias-scrollbar-thumb【不存在】，
    真实存在的是 --dsh-scrollbar-thumb（dsh 前缀不是 dsw）
```

**实测结果**

```
深色块（浅色主题下不该有）：14 处 → 2 处
  剩的 2 处都是合理的：预览画布黑底（视频画面区）
```

### 2.2 标尺改成秒显示
上游 `ruler-utils.ts`：

```
LABEL_FRAME_INTERVALS: [2, 3, 5, 10, 15] → [2, 3, 4, 6, 12]
```

**为什么**：原来 5/10/15 都不整除 24fps，一旦缩放跨过 3 帧，标签就再也落不到整秒，
用户看到的永远是一串帧号（10f/20f/6f/16f/2f/12f…），像 bug。

实测修复后标尺：`00:00 / 00:00.5 / 00:01 / 00:01.5 / 00:02 …`（单调递增，零帧号）

## 三 · 三个根因（这是本轮最值钱的发现）

写进 `docs\踩坑-UI收口三根因-20261021.md`：

```
① 13 个语义色类在 ArtCraft 的 CSS 里【零定义】
   ⇒ 元素回落浏览器 UA 默认灰 rgb(107,107,107)
   ⇒ 这才是「不像原生」的最大来源
   判据：造一个裸 <button> 对比底色，一样就是 UA

② 按钮同时带 size-7 + h-8 + w-8，h-8(2rem=32px) 排在后面胜出
   ⇒ 量尺寸看到「比预期大 4px」，先看有没有成对的 size- 与 h-/w-

③ --st-panel 比 --st-bg 更暗，而 DSH 的 layer-1 比 base 更亮
   ⇒ 两套层级方向相反，必须按语义映射，不能按名字对等
```
