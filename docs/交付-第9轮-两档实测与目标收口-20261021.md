## 一 · 两档宽度实测（试了四种方法，只有一种真的改变布局）

```
方法                                    结果
① window.resizeTo()                    浏览器拦截，无效
② CDP Emulation.setDeviceMetricsOverride  被页面的 resize 逻辑重置
③ 给 DSH 外壳 .BynINW_frame 设固定 width   ✅ 真的重新布局
④ documentElement.style.zoom            只缩放渲染，布局宽度不变 ❌
```

**判据**：改完后 `sectionW` 必须跟着变。

```
1912（原生）→ section 1601px
1280        → section  969px
 375        → section  288px
```

**它其实是我上一轮加的功能实现**（资产卡浮层单例状态），不是诊断探针。

处理：加进 `KNOWN_EXCEPTION` 并写明理由 + 判据 + 对应验收脚本。同时提示：
> 若将来改成不挂全局的方案（Context / zustand），改完记得同步改 `verify-popover-singleton.mjs` 的断言。

⇒ 这类「断言把功能当垃圾」的误报，处理方式必须是**登记为例外并说明**，
