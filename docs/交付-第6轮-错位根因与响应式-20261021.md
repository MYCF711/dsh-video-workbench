## 一 · 轨道错位：真正的根因（找了五轮）

### 前四轮的错误方向

```
轮次  我当时的判断                        实际
①   minSize=15 太小 → 提到 58           治标，还锁死了高度
②   缩小轨道行高 65→56                   无关
③   给 ScrollArea 加 min-h-0             对，但不解决错位
④   把内容层 min-h-full 改成 min-h-0     对，但不解决错位
```

### 真正的根因（第 5 轮找到）

```
实测数据（面板 30%）：
  右侧轨道区  scrollTop = 168
  左侧轨道头  scrollTop = 122
                      差 46px  ← 这就是错位量
```

**`syncFollowers` 只在【滚动事件】里被调用。**

面板尺寸变化（拖分隔条）时：
1. 两侧容器的 `scrollHeight` 变了
2. 浏览器各自把 `scrollTop` clamp 到新的合法范围
3. **但没人再同步一次** ⇒ 两侧停在不同位置 ⇒ 名字对不上轨道

### 修法

```tsx
useEffect(() => {
  const id = requestAnimationFrame(() => syncFollowers());
  return () => cancelAnimationFrame(id);
}, [syncFollowers, timelineHeaderHeightValue, tracksViewportWidth]);
```

依赖 `timelineHeaderHeightValue` 是因为它在面板拖动时会变，可以作为「尺寸变了」的信号。

### 实测结果（四档面板高度全部对齐）

| 面板占比 | section 高 | 轨道区 scrollTop | 轨道头 scrollTop | 同步 | 对齐 |
|---|---|---|---|---|---|
| 30% | 180px | 168 | **168** | ✅ | ✅ |
| 40% | 239px | 109 | **109** | ✅ | ✅ |
| 50% | 298px | 50 | **50** | ✅ | ✅ |
| 70% | 417px | 0 | **0** | ✅ | ✅ |

**判据**：任意面板高度下，两侧 `scrollTop` 差 ≤ 1px。

## 四 · 本轮的方法论教训

### ① 「面板太矮」是现象，不是原因

我前四轮都在调 `minSize` 和轨道行高 —— 那些调整让默认视图好看了，
但**错位在面板压到 30% 时依然存在**。

真正的判据不是「轨道 y 是否 ≥ section y」，而是
**「两侧滚动容器的 scrollTop 是否相等」**。

⇒ 教训：一个视觉症状（名字对不上轨道）可能有两个完全不同的成因
（① 布局溢出 ② 两侧滚动不同步）。**我一直在修 ①，而真凶是 ②。**

### ② 修完必须用「极端值」验证

- 默认 42/58 → 对齐（但这是巧合，因为那时两侧 scrollTop 都是 0）
- 压到 30% → 错位 46px（真凶暴露）

⇒ **只测默认状态等于没测**。必须测极端值：最窄、最矮、内容最多。
