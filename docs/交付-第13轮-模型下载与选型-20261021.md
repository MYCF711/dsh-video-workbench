## 一 · 提速：单连接 → 8 线程分块，快 180 倍

### 单连接的实测数据（全部真实下载，不是估的）

```
hf 直连 model.bin          → us.aws.cdn.hf.co    2.63 MB/s   ← 但时常 502
hf 直连 + ?download=true   → us.aws.cdn.hf.co    0.48 MB/s
modelscope                 → cdn-lfs-cn-1        0.37 MB/s
modelscope 4 并发           →                   1.35 MB/s
hf-mirror                  → cas-bridge.xethub   0.12 MB/s
```

**问题：单连接极不稳定** —— 同一个文件这次 200 下次 502，
速率在 0.06 ~ 2.63 MB/s 之间来回跳。

### 解法：8 线程 Range 分块

```
medium 1457MB  →  135 秒（10.79 MB/s）
turbo  1543MB  →   95 秒（10.74 MB/s，含续传）
```

**比单连接快约 180 倍。** 这是这轮最有用的一条经验。

原理：HTTP `Range` 让服务端按字节区间返回，多块互不干扰，
真正能叠加带宽；某块断了只重下那块，不影响别的块。

## 三 · 三模型实测（这是重点）

### 为什么用「困难样本」

我先用干净素材测，结果 **small 四个场景全 100%** —— 测不出差距。
真实 10 秒对话素材上，**三个模型文字完全相同**，只有时间戳毫秒差。

⇒ 必须造困难样本：

| 场景 | 说明 |
|---|---|
| 高噪 5dB | 接近嘈杂街头 |
| 极快语速 Rate6 | 赶稿式连读 |
| 专业词 | `faster whisper` / `声学模型` |
| 噪+快+长 | 三重叠加 |

### 结果（编辑距离准确率）

```
模型      高噪    快语速   专业词   噪+快+长   平均     总耗时
small    100.0    96.3    91.4     63.6    87.8%    4.88s
medium   100.0   100.0    94.3     72.7    91.8%   12.33s
turbo    100.0    96.3    94.3     75.8    91.6%   13.44s
```

### 结论：选 medium

**turbo 并没有因为标称「large 档」就更好**：

| | medium | turbo | |
|---|---|---|---|
| 平均准确率 | **91.8%** | 91.6% | medium 略胜 |
| 极快语速 | **100.0%** | 96.3% | medium 明显更好 |
| 总耗时 | **12.33s** | 13.44s | medium 快 9% |
| 体积 | **1457MB** | 1543MB | medium 小 86MB |

**turbo 在三个维度上都不占优。** 这是反直觉的结论，所以我把它写进了断言
（`verify-asr-models.mjs`），以后不会再按「大就是好」去选。

### 实际的错误对比（噪+快+长）

```
原文：第一步先把音频转成十六千赫兹单声道波形文件，然后交给识别引擎处理。

small ：第一步先把音琴转成16000Hz单升到波形文件然后交给识别隐形处理  63.6%
         音琴→音频  单升到→单声道  识别隐形→识别引擎
medium：第一步先把音频转成16000Hz单升到波形文件,然后交给识别引擎处理。 72.7%
         只剩「单升到→单声道」
turbo ：第一步先把音琴转成16000赫兹单声道波形文件,然后交给识别隐形处理  75.8%
         音琴→音频  识别隐形→识别引擎
```

medium 只错 1 处，turbo 错 2 处但被字数差异调和成略高分。
**这正是为什么要看逐条错误，不能只看总准确率。**

## 七 · 方法论收获

### 「大模型一定更好」是错的，必须实测

我一开始看到 turbo 1543MB > medium 1457MB，直觉判断「turbo 是 large 档，肯定更强」，
甚至因此放弃了已经下了 425MB 的 medium。

实测打翻了这个判断：**turbo 准确率略低、速度略慢、体积还大**。

⇒ 模型的「档位名字」不等于「这个具体转换版本的效果」。
  `deepdml/faster-whisper-large-v3-turbo-ct2` 和
  `Systran/faster-whisper-medium` 是不同人做的不同转换，
  不能按原模型档位直接比。

### 单文件下载要分块，不是靠换源

我花了很长时间换源（hf / hf-mirror / modelscope / 各种 CDN），
单连接最好也就 2.63 MB/s 且不稳定。

真正的解法是**分块并发** —— 一改就是 10.7 MB/s。

⇒ 判据：**当「换源」的提升有限且不稳定时，先试「并行」。**
  带宽限制通常按连接算，不按总流量算。
