## 四 · 实测到三个真 bug（这是本文核心）

### 4-A 🔴 左组被压扁：工作流名字被截断

```
左组可用宽度   1332.3px（row 1593 − padding16 − gap12 − 右组232.7）
左组实际宽度    322.0px   ← 只用了 24%
内容自然宽合计  306.1px（81.5 + 45.4 + 45.1 + 52.1 + 82）
```

左组 `flex: 0 1 auto` + `overflow: hidden`，在 `space-between` 下被算成最小尺寸，
于是五个控件一律压到 **56px**（工作流真需要 81.5px）：

```
实测按钮宽：工作流 56.0 / 画幅 45.4 / 时长 45.1 / 步数 52.1 / 武打模式 82
工作流文字可见宽：34.5px，而「多参 H3 ★」自然宽 74.5px
⇒ 截图里显示成「▾ 多..」，「多参 H3 ★」被裁掉
```

**这正是主人上一条抱怨的原话「放在右边太远了，看不见」的同一类症状**，只是这次发生在左边。

**修法**：左组 `flex: 1 1 auto`（不要 `0 1`），子项 `flex: 0 0 auto`，
去掉 `overflow:hidden`。左组拿到 1332px 后，306px 内容绰绰有余。

### 4-B ✅ hover 范围：符合（第②条满足）

```
按钮宽 56/45.4/45.1/52.1；其中三角 7.5px + 文字可见宽 34.5/23.8/23.6/30.6
「额外」21.5px = 左右 padding(4+6) + gap(4) + 三角(7.5)
```

hover 底色铺在 **button** 上，button 宽 = 三角 + gap + 文字 + padding，
**不是整个槽**——第②条成立。⚠ 但 4-A 修好后工作流 button 会从 56 涨到 81.5px，
hover 面会跟着变宽。这仍符合「覆盖需要的文字」的原意，需主人过目确认。

### 4-C 🔴 切选项位移：**第③条已被破坏**

实测（改文字后同步 reflow 再量）：

| 槽 | 切选项后左边缘位移 |
|---|---|
| 工作流 | 0.0px |
| 画幅 | **1.7px**（16:9 → 1:1） |
| 时长 | **3.5px**（5 秒 → 10 秒） |
| 步数 | **5.3px**（10 步 → 4 步） |

**根因**：`field` 常量是 `{ width: "100%" }`，而触发器的 `width: "auto"`。
父 wrapper 宽 = 内容自然宽，所以**前一个槽的宽度会随后一个槽的文字变化**，
把后面的槽整体推动。步数位移最大（5.3px）是因为它的文字跨度最大（23.6↔30.6）。

对比旧版（grid 固定列）：四个槽位移全部 **0.0px**。

**修法**（三选一，推荐 ①）：

```
① 每个槽给写死的最小宽度 + 文字单行省略
   field: { width: 84 }（工作流）/ 56（画幅）/ 60（时长）/ 60（步数）
   触发器 width:100%; 文字 span 加 min-width:0 + ellipsis
   ⇒ 槽宽恒定，文字在槽内省略 → 位移 0，且回到旧版已验证状态

② 保留 auto 宽，但把「文字 span」设成固定宽（按最长选项量）
   最长：多参H3★ 74.5 / 16:9 38.4 / 10秒 45.1 / 20步 45.1
   ⇒ 文字居中不齐，视觉上三角与文字间距会变化，不推荐

③ 整条左组右对齐 + 用 flex-direction:row-reverse
   ⇒ 位移从「向右推」变「向左推」，位移量不变，等于没修
```

## 六 · 种子框：确实缺 box-sizing，但**新版已不再压到生成键**

### 6.1 旧版（改造前）—— 是真 bug

```
父槽 96px，input 渲染成 112px（96 + padding 8×2）
input 右边缘 1825 > 生成按钮左边缘 1817
⇒ input 右边 8px 压进了「生成」按钮下面（实测重叠 8px）
```

### 6.2 新版（现任实装）—— 缺 box-sizing 仍在，但不重叠

实测 19499：

```
seedBoxSizing     content-box        ← 仍然缺 border-box
seedCssWidth      92px
seedRenderedW     108px              ← 92 + 8×2，比声明的宽 16px
seedRight         1822.3
genBtnLeft        1826.3
seedOverlapsGen   false              ← 差 4px，恰好没压上
```

结论：**问题是真实存在的（content-box + 108px > 92px），但当前布局下没触发重叠**，
只差 4px 余量。一旦卡片按 §5 收窄到 952px、右组变窄，这个 4px 余量可能被吃掉。

**建议一并修**：第 703 行加 `boxSizing: "border-box"`，把 108px 收回 92px，余量从 4px 变成 20px。
