# 布局重设计方案 · 剪辑台（2026-10-21）

> 主人原话：
> 「目前的布局是dsh里面的中栏的tab，然后在tab里面放的类似PR的软件布局，
>   这样整块屏幕被切割的很碎，不像一个整体。不如视频工作台那样简洁。
>   是不是可以把左边的全部移动到右侧，统一成一个区域？
>   这是我初步想法，你自己重新设计，要求是最终成品是DSH风格和DSH设计语言，
>   整个dsh的软件画面切到时间轴（改名叫剪辑台）的时候不突兀，
>   像原生就有这个功能一样。」

---

## 一 · 先看清现在为什么「碎」

### 当前：四块可拖拽面板（PR 的形状）

```
┌──────────────────────────────────────────────────────┐
│  DSH tab:  对话 | 轨迹 | 视频工作台 | 剪辑台            │
├────────────┬────────────────────────┬────────────────┤
│            │                        │                │
│  素材面板   │       预览区           │   属性面板      │  ← 三列
│  (264px)   │                        │                │
│            │                        │                │
├────────────┴────────────────────────┴────────────────┤
│                    时间轴                              │  ← 一行
│  [17 个图标按钮]                                       │
└──────────────────────────────────────────────────────┘
```

**问题在哪**：

1. **四块，三个可拖边界** —— 加上 DSH 自己的两个列宽手柄，屏幕上共有 **5 条可拖竖线**。
   主人的 ④ 号问题（拖到 DSH 侧栏）就是这些线打架。
2. **素材面板挤在最左**，只有 264px，装什么都要出滑块（③ 号问题）。
3. **属性面板独立一列**，但它只在「选中一个片段」时才有内容 —— 大半时间是空白。
4. **每块都有自己的背景色和边框**，视觉上是四个方框拼起来，不是一整块画布。

### 对比：视频工作台为什么「简洁」

```
┌──────────────────────────────────────────────────────┐
│  工具栏（一行，图标 + 文字标签）                        │
├──────────────────────────────────────────┬───────────┤
│                                          │           │
│           主内容区（一大块）                │  窄侧栏    │
│                                          │           │
└──────────────────────────────────────────┴───────────┘
```

**两块。一条可拖边界。** 主内容占 80%+，侧栏是辅助。

⇒ 差距不是「样式」，是**结构**：碎是因为分了四块。

## 二 · 新布局：两块 + 一条边界

### 设计原则

```
原则 1  屏幕只切两刀：一横（工具栏）一竖（侧栏）
        ⇒ 可拖边界从 3 条降到 1 条，加上 DSH 的 2 条 = 3 条（不是 5 条）

原则 2  时间轴是主角，占最大的面积
        剪辑台的核心动作 90% 发生在时间轴上

原则 3  素材、属性、字幕全部收进右侧一个「检查器」
        按需切换，不再各占一列

原则 4  工具栏一行到底，不占竖向空间
```

### 布局图

```
┌────────────────────────────────────────────────────────────────┐
│ DSH tab:  对话 | 轨迹 | 视频工作台 | 剪辑台 ←（改名）             │
├────────────────────────────────────────────────────────────────┤
│ ① 顶部工具条（44px，一行）                                       │
│   [+ 导入]  [分割 Ctrl+K] [删除 Del]  ·  |  撤销 重做  |  缩放 ──●──  行高  │
│   ───────────────────────────────────────────────────────────  │
│ ② 预览 + 时间轴（同一块，上下排，中间无边框）                      │
│  ┌──────────────────────────────────────────────────────────┐  │
│  │                    预览（16:9 居中）                       │  │
│  │              ▶ ──────●────────── 00:00:02:08              │  │
│  ├──────────────────────────────────────────────────────────┤  │
│  │ 轨道区（五轨，占满剩余高度）                                 │  │
│  │ 视频2 ▏                                                   │  │
│  │ 视频1 ▏████████  ████████                                 │  │
│  │ 音频1 ▏▓▓▓▓▓▓▓▓                                          │  │
│  │ 音频2 ▏                                                   │  │
│  │ 字幕  ▏████  ████                                         │  │
│  └──────────────────────────────────────────────────────────┘  │
└────────────────────────────────────────────────────────────────┘
                                                    ↑
                          右侧「检查器」抽屉（点击才展开，默认收起）
```

### 右侧检查器（收编三块面板）

主人说「把左边的全部移动到右侧，统一成一个区域」—— 就是这个。

```
┌─────────────────────────────┐
│  检查器          [×]         │
├─────────────────────────────┤
│  素材 │ 属性 │ 字幕          │  ← 三个 tab（不是三列）
├─────────────────────────────┤
│                             │
│   （当前 tab 的内容）         │
│                             │
│   宽 320px，从右侧滑入         │
│   半透明磨砂 + 16px 圆角       │
│   不挤压时间轴（覆盖在上层）     │
│                             │
└─────────────────────────────┘
```

**为什么用抽屉而不是常驻列**：
- 常驻列会永久吃掉 320px，时间轴变窄
- 抽屉覆盖在上层，需要时才看，不需要时时间轴满宽
- DSH 自己的右侧栏就是这种模式（`--dsw-menu-surface-fill` + blur）

## 三 · 和 DSH 对齐的具体规格

### 顶部工具条（44px）

```
高度    44px（DSH 的 tab 行 25 + 留白）
底色    var(--dsw-alias-bg-layer-1)
下边框  0.5px var(--dsw-alias-border-l3)
内边距  0 12px
间距    组内 gap 4 / 组间 gap 12 + 分隔线

按钮：
  次要（图标）    28×28，圆角 8，透明底，hover rgba(0,0,0,0.04)
  次要（图标+文字）高 28，padding 0 8，同上
  主操作（导出）  高 32，圆角 8，品牌色底，白字
```

### 预览 + 时间轴（一块，无中间边框）

```
预览区  自适应，上下 padding 12，左右 padding 16
        画面居中，max-height 计算后留出时间轴空间
        进度条：高 2px，hover 变 4px，不用滑块圆点（DSH 风格是细线）

时间轴  顶部一条 32px 标尺行
        轨道头宽 92px（比现在 136 窄 —— 因为名字缩短了）
        轨道之间 0.5px 分隔线，不用 6px gap
        ★ 五轨紧贴，不用 gap：DSH 的分组靠线不靠空隙
```

### 右侧检查器抽屉

```
宽        320px
位置      position: absolute; right: 0
圆角      16px（外侧三边）
底色      var(--dsw-menu-surface-fill) + backdrop-filter: blur(40px) saturate(150%)
阴影      var(--dsw-elevation-prominent)
留白      8px（距 DSH 边缘）
进场      从右滑入 160ms ease-out + 淡入
tab 行    高 36px，三个 tab，选中态底部 2px 品牌色条
```

## 四 · 工具栏：17 个 → 6 个

### 先回答主人的问题：「向左分割和向右分割有什么用？」

**实测结论：它们确实是多余的。**

PR 里只有一种「添加编辑」（`Ctrl+K`）—— 在播放头位置切开。
ArtCraft 的「向左/向右分割」是「从入点切到出点」的两种变体，
但**我们的界面里没有「入点/出点」概念**（那是 PR 的序列工作区功能）。

⇒ **删掉这两个**。只留一个「分割」。

### 新的工具栏（6 个操作 + 1 组缩放）

```
[+ 导入]   ← 主操作，唯一带文字的实心按钮

[分割  Ctrl+K]  [删除  Del]  [复制  Ctrl+D]     ← 三个带文字的次要按钮
|                                                （用快捷键标注代替 tooltip）
[撤销 Ctrl+Z]  [重做 Ctrl+Shift+Z]

                    ──────────  缩放 [−]──●──[+]   行高 [−][+]

                                                 [导出 →]  （在右上角）
```

**11 个收进「···」二级菜单，并标注快捷键**：

| 功能 | 快捷键（PR 对照） | 为什么收进去 |
|---|---|---|
| 提取音频 | — | 低频 |
| 定格帧 | — | 未实装 |
| 添加书签 | `M`（PR 标记） | 低频 |
| 关键帧 | — | 低频 |
| 自动吸附 | `S`（PR 在时间轴中对齐） | 设置项，不是操作 |
| 波纹编辑 | `B`（PR 波纹工具） | 低频 |
| 向左/右分割 | — | **删除**（见上） |
| 场景切换 | — | 低频 |
| 增高/减矮轨道 | `Ctrl+=` / `Ctrl+-`（PR） | 低频，或进菜单 |

## 五 · ④ 号问题的解法（主人说「修好就行」）

**真相**：DSH 的两个列宽手柄在 `x=612` 和 `x=1570`，
ArtCraft 铺满中栏后把它们盖住了。鼠标落在那条竖线上时，事件被手柄接管。

**主人的意思**：「只要能够让鼠标选不到那个滑块就可以了」。

**解法**（治标但安全）：给 ArtCraft 的根容器加**两个不可穿过的空洞**：

```css
/* 在最外层包一层，让 DSH 手柄的位置留空 */
.ac-scope {
  /* DSH 手柄在 viewArea 内的相对位置 = 手柄x - viewArea.x */
  /* 612-280 = 332, 1570-280 = 1290 */
}
```

更简单的做法：**给 DSH 手柄提升 z-index，并让 ArtCraft 不接收那块区域的事件**。

但**最干净的是第三条**：既然新布局下时间轴要占满中栏，
那 DSH 的这两个手柄本来就不该出现在剪辑台里 ——
**让剪辑台这个 tab 全屏时 DSH 手柄隐藏**。

⇒ 实装时验证：切到剪辑台，DSH 手柄是否还在；如果在，用 CSS 让它 `display:none`
  （只在 `.ac-scope` 存在时）。

## 六 · ⑤ 号问题的解法

```
缺陷 A  拖不回
  explicit 失败时静默返回 null
  修：失败要报错 + 视觉反馈

缺陷 B  幽灵「音频」轨
  拖放解析失败 → fallback 到 auto → firstAvailable 装不下 → 新建轨
  修：音频/视频轨全满时【不新建】，报「没有空位」
```
