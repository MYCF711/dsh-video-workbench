## 一 · 怎么复用 dsh-editor 那套（没有重造）

**结论：读它、不写它；另外两源自己扫。**

| 源 | 从哪来 | 为什么这样 |
|---|---|---|
| `editor` | `GET /timeline/assets`（dsh-editor 已有的 11 条） | 那是另一个包的素材库，硬约束是「不动别人的包」。**只读**，不复制、不搬文件 |
| `output` | 自己扫 `D:\Comfy-Desktop\ComfyUI-Shared\output`（486 条） | dsh-editor 不知道这个目录 —— 那是 ComfyUI 的落点，它只登记「显式 add 过的路径」 |
| `input` | 自己扫 `...\ComfyUI-Shared\input`（125 条） | `uploadImage` 就落这儿，是「我上传的」那一类 |

**为什么不把 dsh-editor 的 `assets.mjs` 直接拿来当全局库：**
它只能登记「已显式 add 过的路径」，不扫 ComfyUI 的 `output/`。而且一旦把 611 个文件物理搬进一个新目录，
ComfyUI 的 `/api/view`（按 output/ 寻址）与 dsh-editor 的时间轴引用会同时断链。
⇒ **只读扫描 + 旁挂一份状态（收藏/别名/隐藏/回收），一个字节都不搬。**

**新写的只有三块：**

```
lib/asset-scan.js    192 行   扫盘 / 三源合并 / 排序 / 状态文件 / 移入回收区
lib/index.js         +245 行  /library /file /mutate 三条路由（+ canvas 是画布房间加的）
src/AssetLibrary.js  1450 行  @ 选择器 / 面板 / 票据条 / 换槽浮层 / 胶囊高亮
```

类型判定表（`kindOf`）与 dsh-editor 的 `assets.mjs` 逐项同表，但不 `import` 它 —— 跨包引用会让这个包依赖另一个包的内部实现。

## 二 · @ 引用的数据流（从打字到 ComfyUI 拿到文件名）

```
① 用户在 textarea 打 `@`
   ↓  onChange 正则 /(^|\s)@([^\s@]*)$/ 命中光标前那段
② 浮层弹出（portal 到 body，贴光标）
   候选 = 612 条库数据本地过滤（收藏优先 → 时间倒序 → 类型分组）
   键盘在 textarea 上：↑↓ 移动 / Enter 插入 / Esc 关闭
   ↓  选中
③ applyAsset(it)
   ├─ 当前模式有【空着的 media 槽】 → 绑进那个槽（kind 必须匹配，否则置灰+tooltip）
   ├─ 槽都满了                      → 弹「槽都满了 —— 替换哪一个？」或「只作文本引用」
   └─ 当前模式没有 media 槽（krea2/qwen21） → 只插文本标记（这条分支已实测）
   ↓
④ fetchAsFilePayload(it)
   GET /comfy-assets/file?src=&rel=   ← 同源代理，白名单校验
   → ArrayBuffer → base64 → { base64, filename, kind, assetId, src, rel, displayName, preview }
   ↓
⑤ setFiles({ [slot]: payload })          ← 走 WorkbenchView 已有的 MediaSlots 那条路
   同时 prompt 里插入 `@显示名`，下方出现票据 `[@显示名 | →槽名 | ×]`
   ↓
⑥ 点生成 → params.files = { [slot]: { base64, filename } }   （这段是原有的，一行没改）
   ↓
⑦ POST /comfy-bridge/generate → comfy.uploadImage(buf, filename)
   → 落到 ComfyUI 的 input/ → 返回实际文件名
   ↓
⑧ buildPrompt 把文件名写进 bind 的 media 映射：
   qwen21-edit: ref_image_0 → node 470.image，ref_image_1 → node 475.image
   ↓
⑨ ComfyUI /history 里 node 470 的 image 值 = 你选的那张图
```

**关键：文字标记只是票据，真正进工作流的是 `files[slot]`。**
这是主人「引用必须能真的影响生成结果，不能只是文字好看」那条要求的落点。

**为什么复用 MediaSlots 而不另开上传通道：** 那条路已经真机验过（uploadImage → 节点 image 值）。
另开一条就要再验一遍「文件怎么进 ComfyUI 的 input/」，多一条未验证路径 = 多一个主人验收时才会发现的黑洞。

### 顺手补的一个坑（不补就是假功能）

提示词存在 `sessionStorage`，**槽绑定原本没存**。
实测：切 tab / 刷新回来，`@HD重绘` 文字还在、`files` 是空的 → 界面看起来引用了，实际什么都没送进去。
⇒ 加 `/slotrefs` 持久化（只存 `id/src/rel/显示名` 几百字节，不存 base64 —— 20MB × 10 槽会写爆缓存），
重新挂载时按引用把字节重新取一遍再重建。**实测：刷新后两个槽都自动复原。**

   但 `uploadImage` 对非图片的行为没实测。

4. **画布实际的拖拽位置在刷新后复原** —— 只验了端点 GET/POST 往返（`view`/`pos` 字节一致），
   没有拖一张卡 → 刷新 → 肉眼确认它还在原处。前端逻辑是另一位成员写的，我没动 `AssetCanvas.js`。
5. **20MB 上限边界** —— 代码里有判断，没拿一个大文件真试。
6. **@ 浮层在手写中文输入法组字状态下的行为** —— 加了 `isComposing`/`keyCode 229` 保护
