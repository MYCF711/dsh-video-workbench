## 二 · 真实的缺口（本轮要做的）

### G1 · 资产卡操作区溢出（★ 功能性缺陷，最高优先）

**实测数据（2026-10-21）**：

```
改前：卡片 202px，7 个控件总宽 356px
      6 个溢出卡片右边界，最大超出 172px（压到隔壁卡片）
      flex-wrap: nowrap ⇒ 不换行，直接压过去
```

**后果**：用户想点某张卡的「删除」，实际点到右边那张卡 —— **点错对象**。

**已完成部分**（本轮已做）：
```
✅ 操作区改成 3 常显（参考用途 / @引用 / 更多）+ popover 收纳 5 个低频
✅ 实测 37 张卡，溢出卡数 0，最大超出 0px
✅ 卡宽压到 140px 仍零溢出（临界点 120px）
✅ popover portal 到 body（不受卡片 overflow 裁切）
✅ 内容 6 项，无重复
```

**未完成**：
```
⬜ popover 的「点外面关闭」「Esc 关闭」未实测
⬜ popover 在窄视口下的位置未验（可能超出屏幕）
⬜ 暗色主题下的 popover 底色未验
```

### G2 · 调试探针残留在生产代码

**实测**：`AssetLibrary.js:3672-3679` 有 `window.__AT_DEBUG__` 探针，
注释写着「★ 临时探针（查完删）」—— **没删**。

**为什么是真问题**：
```
① 每次按键都往 window 上 push 数组，长会话会累积
② 它记录 val / caret / hit —— 用户输入的提示词被复制到全局变量
③ 说明「临时」的东西没清理，下一个读代码的人会以为它有用
```

### G3 · 空态没有实时资产数（草稿 U6 的遗漏）

**实测**：空态显示「从资产库引一张」，但**没有数字**。
主人打开前不知道里面有 875 项。

**判据**：数字必须从 `/library` 实时取，不能写死（AGENTS §6.40 判据二）。

### G4 · 漏翻检测脚本（草稿 T4，真的没做）

**为什么需要**：时间轴现在零英文，但将来改文案可能漏。
需要脚本守住，而不是靠人眼看截图。
