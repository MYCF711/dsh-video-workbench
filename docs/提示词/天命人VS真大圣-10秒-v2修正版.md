# 天命人 VS 真大圣 · 10 秒 · 修正版（v2）

> 依据 2026-10-23 实测 `view (1).mp4` 的诊断结论重写。

## 一 · 实测证据（v1 失败原因）

| 项 | 实测值 | 判读 |
|---|---|---|
| 总帧数 | 243 帧 @ 24fps | 10.13 秒 |
| 切点帧 | 54 / 88 / 131 / 169 / 208 | = 2.25/3.67/5.46/7.04/8.67s |
| v1 写的切点 | 2.20 / 3.60 / 5.40 / 7.00 / 8.60 | **逐镜吻合，时间控制成功** |
| 第 20 帧 | 三个角色在空中 | 角色复制 |
| 第 90 帧 | 右侧两个白毛大圣并列 | 角色复制 |
| 第 156 帧 | 三人 + 一根无人持的长棍 | 角色复制 + 道具脱离 |
| 分区锐度（帧 115） | 上方云 0.77 / 下方石 6.35 / 人物区 **2.68** | 背景清晰，人物糊 ⇒ 运动物体糊，非全局降质 |
| steps | 12 | 偏少 |
| megapixels | 1.0（→1376×768） | 6 镜快切不够分 |
| 动作向 LoRA 合计 | 2.15（0.65+0.35+0.35） | 叠加过载 |
| speed slider | +3 | 正加速，进一步放大位移 |

### 根因算术

```
第 3 镜：8 个动作节拍（旋棒/低扫/上撩/下劈/硬接/直刺/闪避/划破）
时间预算：1.80 秒 × 24fps = 43 帧
⇒ 每 5.4 帧一个动作节拍
⇒ 一个完整「起势-挥击-命中-收势」最短需 ~24 帧
⇒ 不可能完成 ⇒ 模型把多个姿态同时画进去 = 三个影子
```

**结论：残影是动作密度超载，不是 LoRA 坏了。LoRA 只是放大器。**

## 二 · v2 设计原则（每条都对应一个 v1 的失败）

| 原则 | 治哪个病 |
|---|---|
| **3 镜，每镜 ~3.3 秒（80 帧）** | 动作节拍有地方落地 |
| **每镜最多 2 个动作节拍** | 每节拍 ~40 帧，物理可行 |
| **全程两人同框，不用极特写** | v1 的 Shot 2 极特写裁掉对手，导致单棍单人 |
| **相邻镜头的景别跨度 ≤ 一级** | v1 从极特写跳全景，模型接不上 |
| **只写单一、连续的动作**，不写「三连击」 | 不给模型塞多个姿态的机会 |
| **明确写「the other fighter remains in frame」** | 强制保持两人，抑制复制 |
| **位移幅度收窄**（不写 twenty-meter gap / drops from upper frame） | 大位移 + 低像素预算诱发复制 |

## 五 · 参数调整（按优先级，先做 1~3 再考虑动 LoRA）

| # | 项 | v1 | v2 建议 | 理由 |
|---|---|---|---|---|
| 1 | 镜头数 | 6 | **3** | 根本修正 |
| 2 | 每镜动作节拍 | 最多 8 | **≤2** | 根本修正 |
| 3 | megapixels | 1.0 | **1.5** | 像素预算够分，锐度提升 |
| 4 | steps | 12 | **18~20** | 动作帧需要更多采样步数收敛 |
| 5 | speed slider | +3 | **0 或 -2** | 正加速放大位移，诱发复制 |
| 6 | 动作 LoRA 合计 | 2.15 | **≤1.0** | 若 1~5 做完仍有复制再动这条 |

**关于第 6 项**：`yz.bind.json` 的 `wudA` 是**全开或全关**的二元 toggle，不能单独关某一个 LoRA。
要精简必须改 `yz-ultimate-full.json` 里的 `strength_model`，或在 bind 里加单 LoRA 开关。
**先不要动** —— 改 1~5 大概就够；真不够再改工作流，并先备份 `.bak`。
