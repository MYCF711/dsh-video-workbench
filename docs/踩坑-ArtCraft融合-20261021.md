## ① MediaTime 是整数 tick，不是 `{numerator, denominator}`

**证据（`video-editor/src/lib/wasm/media-time.ts` 逐字）**

```ts
// Integer-tick time. Mirrors MediaTime(i64) in rust/crates/time/src/media_time.rs.
export type MediaTime = number & { readonly __mediaTime: unique symbol };
export const TICKS_PER_SECOND = _TICKS_PER_SECOND();

function isMediaTime(value: number): value is MediaTime {
  return Number.isInteger(value);
}

export function addMediaTime({ a, b }) {
  return requireMediaTime({ value: a + b, context: "addMediaTime()" });
}
```

**实测值**：`TICKS_PER_SECOND = 120000`（`node` 里 `import("opencut-wasm").TICKS_PER_SECOND()`）

**错误**：我把 `{numerator, denominator}` 当时间传进去。
`addMediaTime` 里 `a + b` 变成 `"[object Object][object Object]"` ⇒ 抛错
`expected an integer tick count`。

**根因**：`{numerator, denominator}` 是 **FrameRate（帧率）** 的类型，不是时间。两者搞混了。

**后果**：整个投影的时间表示全错，时间轴渲染失败、一片空白。

**修**：
```js
export const TICKS_PER_SECOND = 120000;
export function secToTime(sec) { return Math.round((Number(sec) || 0) * TICKS_PER_SECOND); }
export function timeToSec(t) { return (typeof t === "number" ? t : Number(t)) / TICKS_PER_SECOND; }
```

## ② tracks 是 `{ overlay, main(单个对象), audio }`

**错误**：写成 `{ video: [...], audio: [...] }`。

**报错**：`scene.tracks.overlay is not iterable`

**根因**：
```ts
// 真实的 SceneTracks 形状
tracks: {
  overlay: [],     // 叠加轨数组
  main: { ... },   // 【单个】主轨对象，不是数组
  audio: [],       // 音频轨数组
}
```

- `video` 这个键**根本不存在**，ArtCraft 找的是 `main`
- `overlay` 缺失 ⇒ iterate 时拿到 `undefined`

**教训**：`video` 与 `audio` 都是轨道，很容易想当然认为形状一样。
**实际是 main 单数、audio 复数。** 要看 ArtCraft 自己的 `buildDefaultScene` 怎么造，不能类比。

**⚠ 这个坑踩了两次**：修好后用 `Copy-Item` 同步时，把工作台那份旧的覆盖了 ArtCraft 修好的那份 ⇒ 回归。

**纪律**：两份文件（工作台 `timeline-projection.mjs` / ArtCraft `dsh-projection.ts`）必须同时修，
单向覆盖前先确认哪份是新的。

## ③ `element.type` 按实际扩展名判，不是 `clip.kind`

**错误**：
```js
const kind = clip.kind === "audio" ? "audio" : (clip.kind === "image" ? "image" : "video");
```

**根因**：`clip.kind` 表示「**在哪条轨上**」，不是「媒体是什么类型」。

**实测**：那个 clip 在视频轨上（`kind="video"`），但 `rendered.filename` 是 `.png`。
判成 `type:"video"` ⇒ ArtCraft 用 `<video>` 去加载 PNG ⇒ 加载失败 ⇒ 静默不显示缩略图。

**修**：按文件扩展名判
```js
const IMAGE_EXT = new Set([".png", ".jpg", ".jpeg", ".webp", ".gif", ".bmp", ".avif"]);
const AUDIO_EXT = new Set([".mp3", ".wav", ".m4a", ".aac", ".flac", ".ogg", ".opus"]);
const kind = AUDIO_EXT.has(ext) || clip.kind === "audio" ? "audio"
  : IMAGE_EXT.has(ext) ? "image" : "video";
```

## ④ `duration = trimEnd - trimStart`，不是 `out - in`

**错误**：`duration` 恒等于源素材全长 `out - in`，只改 `trim`。

**后果（静默失效）**：界面**毫无变化**、导出仍按全长。
看起来「保存了」，实际没生效。

**语义**（ArtCraft）：
```
duration    这个 element 在时间轴上【占多长】
trimStart   从源素材的哪个位置开始取
trimEnd     取到源素材的哪个位置
⇒ duration === trimEnd - trimStart（未设 trim 时等于全长）
```

**修**：
```js
const trimStartSec = Number(clip.trim?.startSec) || 0;
const trimEndRaw = Number(clip.trim?.endSec);
const hasTrim = Number.isFinite(trimEndRaw) && trimEndRaw > trimStartSec;
const effectiveDur = hasTrim ? (trimEndRaw - trimStartSec) : dur;

element.duration = secToTime(effectiveDur);
element.trimEnd = secToTime(hasTrim ? trimEndRaw : dur);  // 没裁切时必须写全长，不能写 0
```

## ⑤ `startTime` 累加用 element 实际时长

**错误**：`t += dur`（`dur = out - in`）。

**症状**：两个 clip 之间出现 **3.5 秒空隙**，总时长 8 秒（应为 6.5）。

**根因**：`el.duration` 已按 trim 算成 1.5 秒，但游标却按 5 秒前进。

**★ 为什么单 clip 时发现不了**：只有一个 clip 时没有「下一个 clip 的位置」，空隙不可见。

**修**：`t += timeToSec(el.duration)`

**★★ 方法论**：**位置类 bug 需要 ≥2 个元素才暴露。**
单元素测试对「布局/偏移/累加」这类缺陷是盲的。

## ⑥ `AudioElement` 必须声明 `sourceType`

**证据（`types.ts` 逐字）**
```ts
export type AudioElement = UploadAudioElement | LibraryAudioElement;

export interface UploadAudioElement extends BaseAudioElement {
  sourceType: "upload";
  mediaId: string;
}
export interface LibraryAudioElement extends BaseAudioElement {
  sourceType: "library";
  sourceUrl: string;
}
```

**错误**：两个都没设。

**ArtCraft 的合成代码**：
```js
if (element.sourceType === "upload") { …mediaMap 查资产… }   // 不进（undefined）
if (element.buffer) return element.buffer;                    // 不进（没预解码）
const response = await fetch(element.sourceUrl);              // ← fetch(undefined)
```
`fetch(undefined)` 抛错 → `catch` 里 warn → 返回 null →
`createTimelineAudioBuffer` 见 `audioElements.length === 0` 就返回 null
⇒ **导出只有视频流，没有音频流**。

**★ 症状极隐蔽**：时间轴上音频条带**正常显示**（那是另一条渲染路径），
只有导出文件里少音频流。光看界面完全看不出来。

**修**：`element.sourceType = "upload"`（我们已有媒体注册，走资产表那条路）。

**验证（ffmpeg）**：
```
修复前: 1375.1KB  Stream #0:0 Video            ← 只有视频
修复后: 1564.7KB  Stream #0:0 Video
                  Stream #0:1 Audio aac 44100Hz stereo 191kb/s
```

## ⑦ `mediaId` 必须是资产表里的真实 id

**错误**：靠「`src` 是否绝对路径」猜前缀。

**实测**：
```
资产表真实 id = "editor:<WORKSPACE>\资产库\音频\test-mix.m4a"
投影猜出来的   = "output:test-mix.m4a"        ← 不存在
```

**根因**：投影是纯函数，拿不到资产表。而音频资产的 `src` 是 `editor`（来源标签），不是 `output`。
**视频恰好猜对了**，因为它们的 `src` 就是 `output`。

**后果**：`output:test-mix.m4a` 在资产表里不存在 ⇒ 音频条带不渲染、也不注册媒体。

**修**：在能拿到资产表的地方（`client.js`）按文件名修正
```js
export function fixupMediaIds(project, libraryItems) {
  // ① 精确 id 命中 → 不动
  // ② 用 rel 的 basename 在资产表里找 name 相同的 → 用它的 id
  // ③ 找不到 → 保留原值
}
```

**★ 为什么用文件名而不是完整路径**：投影已把路径 norm 成 `/`，而资产表的 `rel` 可能是 `\` 或绝对路径。
跨两种分隔符做路径相等判断很容易出错，文件名是稳定锚点。

## ⑧ payload 必须 base64（否则 esbuild 导出被劫持）

**现象**：时间轴 tab 存在，但内容区空白、没有任何报错。
`data-slot-error="conversation.view"`，`hasArtcraft: false`。
CSS 注入了（说明代码跑到那一步），但 `.ac-scope` 容器不存在。

**探针结果**：
```
applyCalled:  {at:..., stage:"start"}   ← apply 被调用了
hostRendered: 4                          ← 组件渲染了 4 次
hasScope:     false                      ← 但容器不在 DOM
trace:        []                         ← effect 一次都没跑
```

**根因**：payload（ArtCraft 的 8MB CJS 源码）里有
```js
var dsh_entry_exports = {};
__export(dsh_entry_exports, { mount: ..., toProject: ..., unmount: ... });
module.exports = __toCommonJS(dsh_entry_exports);
```

**esbuild 做 CJS 导出分析时不区分内容是否在字符串里。**
它在整个 bundle 里扫到这两行，就把它们当成本模块的导出声明：

```
最终产物导出：__export(dsh_entry_exports, { mount, toProject, unmount })   ← ArtCraft 的
应该是：      __export(xxx_entry_exports, { apply, inject, name })          ← 我的
```

⇒ `exports.apply` 消失 ⇒ **DSH 拿不到 apply ⇒ 插件静默不激活**。

**★ 为什么这是最难查的一个**：
- 没有错误、没有日志、tab 还在
- 看起来像「组件渲染失败」或「主题改坏了」
- 实际是打包器的导出分析被 payload 内容劫持

**判据**：查产物里的 `__export(xxx_entry_exports, {...})` 块，
如果里面是 `mount/toProject/unmount` 而不是 `apply/name`，就是这个 bug。

**修**：base64 编码
```js
const b64 = Buffer.from(raw, "utf8").toString("base64");
// base64 只含 A-Za-z0-9+/=，esbuild 扫不到任何代码特征
```

运行时解码：
```js
function decodeArtCraftSrc() {
  const bin = atob(ARTCRAFT_SRC);
  const bytes = new Uint8Array(bin.length);
  for (let i = 0; i < bin.length; i++) bytes[i] = bin.charCodeAt(i);
  return new TextDecoder("utf-8").decode(bytes);
}
```

## 附 · 另外两个（不在八个之内，但同样静默）

### ⑨ 主题轮询触发 React #300

```js
React.useEffect(() => {
  const stop = watchDshTheme(null, cb);   // 每 1 秒 getComputedStyle
  return stop;
}, []);
```

**报错**：`Minified React error #300` = `Rendered more hooks than during the previous render`

**成因判断**：轮询在 React 提交阶段读取布局样式（`getComputedStyle`）会触发强制同步布局，
可能打断 React 的提交流程。

**二分过程**：注释掉这段 effect → #300 消失、ArtCraft 求值成功。

**修**：延迟 1.5 秒启动 + 间隔放宽到 2 秒 + 卸载时清启动定时器。

**★ 这也说明一件事**：`hostRendered: 4` 但 `fatal` 为空时，
错误可能被 DSH 的 ErrorBoundary 吞掉。**必须自建 ErrorBoundary 才看得见。**

### ⑩ 视频的 `thumbnailUrl` 必须是首帧图

```jsx
// timeline-element.tsx:1094 逐字
const imageUrl = element.type === "video"
  ? mediaAsset?.thumbnailUrl              // ← 视频只看这一个
  : (mediaAsset?.thumbnailUrl ?? mediaAsset?.url);

if (!imageUrl) return <span>{element.name}</span>;   // 没有就只显示名字

// 有了之后也不是 <img>，是 CSS 背景横向平铺：
backgroundImage: `url(${imageUrl})`,
backgroundRepeat: "repeat-x",
backgroundSize: `${tileWidth}px ${trackHeight}px`,
```

**错误**：把 mp4 的 URL 直接当 `thumbnailUrl` ⇒ 浏览器解码失败 ⇒ 条带只剩灰底 `rgb(107,107,107)`。

**★ 我还一度判断错了对象**：查时间轴里的 `<img>`，`imgCount=0` 就以为「没渲染」。
条带根本不用 `<img>`，它用 `background-image`。
**「查错了对象」和「查对了但值是错的」是两种不同的错误。**

**修**：canvas 抽第 0 帧
```js
v.currentTime = 0;
v.addEventListener("seeked", () => {
  const c = document.createElement("canvas");
  const MAXW = 480;   // 条带平铺够用，19KB vs 原图几 MB
  ctx.drawImage(v, 0, 0, c.width, c.height);
  const dataUrl = c.toDataURL("image/jpeg", 0.82);
});
```

用 `seeked` 而不是 `loadeddata`，保证画面已解码到目标帧。

**实测**：6 条资产 `thumbnailUrl` 全部是 `data:image/jpeg;base64`（19.4KB），
7 个条带 `DIV.absolute.inset-0` 全部有 `background-image`。

## 两条比具体坑更值钱的方法论

### 一 · 位置类 bug 需要 ≥2 个元素才暴露

```
单 clip  →  时间轴正常，无空隙，看不出问题
双 clip  →  3.5 秒空隙立刻出现
```

**单元素测试对「布局 / 偏移 / 累加」这类缺陷是盲的。**

### 二 · 加一种媒体类型就要独立验它的完整链路

累计 14 个 bug 里，有 4 个是「视频通过但音频失败」：

```
⑤ 资产必须先注册      ⑥ clip.kind 不是媒体类型
⑦ mediaId 前缀猜错    ⑧ sourceType 没设
```

**为什么音频更容易漏**：
- 没有视觉产物 —— 条带画出来就以为对了
- 资产 id 格式不同（`editor:` vs `output:`）
- element 是联合类型，视频不是
- 影响只在导出时体现，不像视频预览就能看出

**纪律**：加一种媒体类型，就要独立验它的完整链路，不要假设「和上一种差不多」。

## 另记一笔 · 验收自己过期也是一种「静默失效」

```
verify-artcraft-storage.mjs 原本写：
  const el = p?.data?.scenes?.[0]?.tracks?.video?.[0]?.elements?.[0];

tracks.video 这个键在 ArtCraft 里根本不存在（是 main）。
验收自己写错了却一直「通过」—— 因为它从没真正读到 element。
```

**这比没有验收更危险**：它让人以为已经覆盖了。

发现方式：改了 `tracks` 结构之后验收变红，才暴露它一直是假的。
⇒ **每次改数据结构，都要看验收是真通过还是假通过。**
判据：故意把被测代码改成错的，验收必须变红。不变红就是假通过。
