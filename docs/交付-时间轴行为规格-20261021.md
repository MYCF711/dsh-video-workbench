## 二 · 轨道顺序改造：20 处硬编码的处置

```
改变前（UI 顺序 = 渲染顺序，共用一个表达式）：
  [...overlay, main, ...audio]
  ⇒ 视频2、字幕、视频1、音频1、音频2      ← 字幕卡在中间

改变后（两个顺序解耦）：
  UI 顺序（display-order.ts / getDisplayTracks）：
    视频2 → 视频1 → 音频1 → 音频2 → 字幕
  渲染顺序（保留 [...overlay, main, ...audio]）：
    overlay 全部在上（含字幕）→ main 在下   ← 字幕仍盖在画面上
```

**20 处判定**（详见 `docs/方案-轨道顺序改造-20261021.md`）：

| 类别 | 处数 | 处置 |
|---|---|---|
| UI 侧（渲染行序 / 拖放落点 / 点击命中 / 吸附 / 整体移动） | **14** | 统一调 `getDisplayTracks` |
| 渲染或无关（混音 / 画布命中 / 时长 / 元素查找） | **6** | 保留原样 + 加「勿改成 UI 顺序」标注 |

**为什么不逐处手写**：漏一处的后果是「渲染用新顺序、命中用旧顺序」⇒ 点击位置与视觉错位，且**不报错、不崩**，只能靠人眼看出来。

## 三 · 本轮自己引入又修掉的问题（值得记）

### ① 材质默认会落到「视频 2」

```
UI 顺序改成「视频2 在前」后，firstAvailable 策略复用同一顺序查找
⇒ 素材会先落视频2，与主人规格「默认落视频1、手动拖才进视频2」相反

修法：放置用独立的 placementOrdered（main 优先），与 UI 显示顺序解耦
判据：resolve.ts 里 firstAvailable 分支必须是 placementOrdered
```

### ② 函数自引用 ⇒ 无限递归

```
group-move/track-placement.ts 原本自己有一个 getDisplayTracks，
我 import 同名函数并把函数体改成 return [...getDisplayTracks({ tracks })]
⇒ 函数调用自己 ⇒ 栈溢出

修法：import 时重命名 getCanonicalDisplayTracks，本地名保留为兼容壳
判据：函数体里出现与函数自身同名的调用 = 自引用
```

### ③ `Menu01Icon is not defined`

```
只改了 JSX 用了菜单图标，忘了改 import 那一行。
esbuild 不做未定义变量检查 ⇒ 构建能过、运行时才炸。
判据：改 JSX 用了新图标，必须同步查 import。
```

### ④ 注释里的反引号会闭合模板字符串

```
dsh-native.css.js 外层是 String.raw`...`，
注释里写 `xxx` 会把模板提前闭合 ⇒ 构建报 "Expected ; but found xxx"
报错指向注释位置，看起来毫无问题。本轮踩了 3 次。
⇒ 已加断言：文件里只能有 2 个反引号（开与闭）。
```
