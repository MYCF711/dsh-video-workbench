## 二 · 数据契约（前端照此实现）

### 2.1 资产 id 格式

```
<src>:<rel>
   src = "output" | "input" | "editor"
   rel = 相对路径（可含 / 子目录）
例：output:Krea2-USD-20261018_00008_.png
    input:voice.wav
```

**这个 id 同时是**：
- 我们资产库的 `item.id`
- ArtCraft 的 `MediaHandle.id`
- 解析成 URL 的唯一依据

### 2.2 两个 adapter 的对接

```js
import { assetToSelection, handleToResolved, filterByKinds } from "./artcraft-adapter.mjs";

const adapters = {
  assetGallery: {
    async openPicker({ kinds }) {
      // ① 用我们的资产库全量过滤
      const sels = filterByKinds(libraryItems, kinds);
      // ② 弹我们自己的选择器（前端 UI 待做），返回用户选中的
      return await myPicker(sels);        // [{handle:{id,kind}, name}]
    },
  },
  mediaSource: {
    async resolveMedia(handle) {
      return handleToResolved(handle, libraryItems);   // {url, mime}
    },
    async uploadLocalFile(file) {
      // 走我们的 /upload → 拿到资产 id
      const it = await uploadToLibrary(file);
      return { id: it.id, kind: it.kind };
    },
  },
};
```

### 2.3 projectStorage 的对接

```js
import { createProjectStorage } from "./artcraft-storage.mjs";

const projectStorage = createProjectStorage({
  store,                 // host-store（要有 snapshot()）
  persister,             // createPersister 的返回值（要有 flush()）
  replaceState,          // ★ 必须提供：把合并后的 state 写回 store
  log,
});
```

**`replaceState` 不能省。** 没有它时 `saveProject` 会明确 warn 而不是假装成功 ——
这是有意的：偷偷只改内存副本会让 UI 看起来保存了、重启就丢。

## 三 · ★ 最危险的一处：saveProject 不能直接覆盖

### 问题

`saveProject(project)` 拿到的是 **ArtCraft 改完的 TProject**。
它的 element 只有这些字段：

```
id, name, duration, startTime, trimStart, trimEnd, mediaId, type, params
```

而我们的 clip 有：

```json
{
  "id": "c_1", "src": "...", "in": 0, "out": 5, "trim": {...},
  "shot":    { "modeId":"yz", "prompt":"人定的提示词", "aspect":"16:9",
               "durationSec":5, "toggles":{}, "media":{}, "history":[] },
  "rendered":{ "path":"...", "generatedAt":1792248820967, "replaced":true },
  "handoff": { "locks": { "prompt": { "by":"user", "fp":"316869238" } },
               "log": [{ "at":..., "by":"user", "field":"prompt" }] },
  "regenError": null, "fromVideoClipId": null
}
```

**直接覆盖 ⇒ `shot` / `handoff` / `rendered` 全部消失，且不报错。**

后果：下次打开时间轴，每一镜的「生成配方」和「谁锁了 prompt」都没了。

### 解法：单一真相 + 单向投影

```
timeline-state.json   ← 唯一真相（含 shot / handoff）
        ↓ toArtCraft()      只读，给 ArtCraft 编辑时间轴
   ArtCraft TProject
        ↑ fromArtCraft()    只回写 trim 与顺序
```

`fromArtCraft()` 只碰两样东西：
- `trim.startSec` / `trim.endSec`
- clip 顺序

**其余字段原样返回。** 这是「范围只取 ArtCraft 的时间轴能力」的正确实现。

### 为什么只取这两样

ArtCraft 还能加特效、动画面、改音量 —— 那些**我们的模型没有**。
硬搬会造出「UI 上能调但后端不认」的摆设参数，
而 M1 参数闭环验收专门防这个（AGENTS §6.25 的教训）。

## 五 · 后端实施中抓出的 bug（都是验收逼出来的）

### ① `mediaId` 取错了字段

```
得到 "output:yz-result.mp4"，应该是 "output:Krea2-USD-....png"
根因：优先取了 rendered.filename
     但 rendered 是「这一镜生成过什么」的历史记录（还有 replaced:true）
语义：src 才是这个 clip 现在引用的媒体
```

### ② `startTime` 不从 0 开始

```
根因：「待生成」的 clip 被跳过，但仍吃掉了 5 秒时间轴，留了个空洞
修：只有真正出现在 ArtCraft 上的 clip 才占时间
```

### ③ `fromArtCraft` 会偷偷挪动 clip 顺序 ← 最隐蔽

```
原顺序  [分镜1(待生成), 分镜2(已生成)]
我的代码 [分镜2, 分镜1]        ← 把待生成的挪到末尾
语义错误：ArtCraft 看不到它，不代表用户希望它被挪走
修：用 ArtCraft 给的相对顺序原地填空，没投影的留在原位
```
