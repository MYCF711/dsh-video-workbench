# 四个下拉全是摆设：控件启用 ≠ 数据会传下去

### 6.25 ★ 四个下拉全是摆设：控件启用 ≠ 数据会传下去（2026-10-19）

```
★★ 这是本项目最严重的一个缺陷。主人调了两天的参数，一个都没生效。

现象：
  界面上「画幅 / 尺寸 / 张数 / 放大模型」四个下拉都能点、能显示、
  能持久化到 sessionStorage，但提交给 ComfyUI 的全是工作流默认值。

根因（WorkbenchView.js 的 onGenerate）：
  const params = { prompt, steps: Number(steps), toggles };
  // 之后只补了 files / refLabels / refWarnings / steps2 / seed
  // 从未补 aspect / megapixels / batch / seedvrModel
  ⇒ grep 这四个字段在 params 上下文 → 零命中

实测证据（复核员劫持 fetch 抓真实 body）：
  界面显示 21:9 / 4K / 4张 / 7B
  实际 body 只有 {prompt,steps,toggles,files,steps2,modeId}
  8188/history 的 prompt 里 aspect:"9:16" mp:1 batch:1（工作流原值）

❌ 为什么一直没被发现
  · 界面显示是对的（state 更新了），看起来「改了」
  · 生成能成功（用默认值也能出图）
  · 输出尺寸「看起来正常」（因为默认 9:16 也合理）
  · 只有对比「界面选的值」与「ComfyUI 收到的值」才能发现

★★ AGENTS §3.13 ② 曾经写过「修：if (caps.aspect) params.aspect = aspect;」
   但 grep 代码 → 这一行【从未存在】。文档说已修，代码没有。
   ⇒ 这就是为什么「写在文档里的修复」不能当证据，必须 grep 代码。

✅ 修（四项都先问 caps，避免给不支持的工作流发多余字段）：
   if (caps.aspect) params.aspect = aspect;
   if (caps.megapixels) params.megapixels = Number(megapixels);
   if (caps.batch) params.batch = Number(batch);
   if (caps.seedvrModel && toggles?.seedvr) params.seedvrModel = seedvrModel;

✅ 端到端实测（2026-10-19，队列空闲时）：
   界面选 21:9 / 1K / 2张
   提交的节点 211: {"aspect_ratio":"21:9 (Ultrawide)","megapixels":1.0}
   提交的节点 210: {"batch_size":2}
   产物: 1568×672，宽高比 2.333，1.05 MP，2 张
   ⇒ 每一个数字都对上了

★★ 排查纪律（新增，以后每次加控件都做）：
   1. 加一个控件，就必须在同一处加它的 params 赋值 —— 两件事一起做
   2. 验证方式不是「看界面」，而是【劫持 fetch 看真实 body】
      或直接查 8188 的 /queue 里的 prompt 定义
   3. 反向检查：grep `params\.<字段名>`，与 UI 上的控件清单比对
   4. 凡「置灰的控件不能传数据」的对偶命题同样成立：
      【启用的控件必须真的传数据】—— 这条之前没人守

★ 附带发现：4K(16MP) × 4 张在 16GB 卡上必然 OOM
  实测：Allocation would exceed allowed memory（26.46 GiB allocated / 15.92 limit）
  UI 目前不拦这个组合也不提示 —— 记为【待定】，属产品取舍。
