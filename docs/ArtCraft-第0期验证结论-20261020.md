## 四、必须的 4 个补丁（按遇到顺序）

### ① wasm-bindgen 适配插件（最难，5 版才成）

`opencut-wasm` 是 wasm-bindgen 的 **bundler 目标**格式：
```js
// opencut_wasm.js
import * as wasm from "./opencut_wasm_bg.wasm";
__wbg_set_wasm(wasm);
wasm.__wbindgen_start();
```

esbuild 不认这个语法。五版演进：

```
① 不处理 → TypeError: (void 0) is not a function
   esbuild 把 .wasm 当普通模块，导入是 undefined

② 导出 default = new Proxy(...) → 仍是 (void 0)()
   `import * as wasm` 走【静态导出分析】。入口写 wasm.__wbindgen_start()，
   而 Proxy 模块的静态导出表里没这名字 ⇒ esbuild 直接编译成 (void 0)()

③ 导出具名 __wbindgen_start → LinkError: Import #0 ... requires a callable
   实例化时 importObject 是空对象

④ 从 bg.js namespace 取 importObject → 实例化成功，但
   TypeError: Cannot read properties of undefined (reading 'grow')
   根因：入口先 __wbg_set_wasm(空壳) 再 __wbindgen_start()，
   而 bg.js 内部 wasm.memory 早指向空壳

⑤ 定稿：模块求值时【立刻】实例化，把真 exports 铺成语义导出
   ESM 保证 import 的 bg.js 先求值 ⇒ importObject 一定是真函数
```

**可复用的插件**：`D:\主工作区\_upstream\artcraft-demo\wasm-plugin.mjs`

### ② react-router 包裹

```
Error: useNavigate() may be used only in the context of a <Router> component
```
编辑器内部用 `useNavigate`/`useLocation`，宿主必须包一层 Router。
**建议用 `MemoryRouter`**（不碰 history，避免与 DSH 路由打架）。

### ③ 项目 bootstrap（两个调用，缺一不可）

`VideoEditor.tsx:152` 的门控：
```ts
if (!gpuReady || !hasProject) return null;
```

只设 project 不够，必须照官方冒烟测试的顺序：
```ts
EditorCore.initialize({ adapters });
const editor = EditorCore.getInstance();
editor.project.setActiveProject({ project });
editor.scenes.initializeScenes({          // ← 缺这行会抛 "No active scene."
  scenes: project.scenes,
  currentSceneId: project.currentSceneId,
});
```

### ④ `fps` 必须是 FrameRate 结构

```ts
// ✗ 错：fps: 30
// ✓ 对：fps: { numerator: 30, denominator: 1 }
//      或直接用 DEFAULT_FPS（video-editor/src/lib/fps/defaults.ts）
```
报错：`invalid type: floating point 30.0, expected struct FrameRate`
⚠ 官方冒烟测试里写的是 `fps: 30 as never`，类型检查绕过了，运行时才炸。

## 五、CSS 隔离（方案书里标注的「最大变数」—— 已消除）

**做法**：Tailwind 3.4.19 预编译 + `postcss-prefix-selector` 加 `.ac-scope` 前缀
+ **关掉 Preflight**（`corePlugins: { preflight: false }`，它会重置全局样式）

**实测结果**：
```
dist/ac.css            51KB
.ac-scope 出现         548 次
--tw-* 变量            61 个（Tailwind 自己的）
--dsw-* 冲突           0 个   ★
未加作用域的顶层选择器   0 条   ★
```

⇒ **CSS 可以干净隔离，不会污染 DSH。方案书里的最大变数不存在。**

⚠ 前提：必须关 Preflight。开了它会注入 `*{margin:0}` 这类全局重置。

## 七、给第 1 期的建议

### 7.1 必须先解决的问题

```
① 体积：2.01MB gzip。要决定「只在打开视频编辑 tab 时动态加载」还是「接受常驻」
   ⇒ 建议动态 import()，但 DSH 的模块加载器要能配合（需查 §6.x）
② 两套图标库：合并掉 lucide-react（或 hugeicons），省约 300KB gzip
③ 主题：ArtCraft 是暗色（#1E1F22）+ 白字，DSH 有明暗两套
   ⇒ 必须把它的 Tailwind 颜色映射到 --dsw-* token，否则明色主题下会黑底白字
```

### 7.2 接入形态建议

```
不要整个替换「粗剪」tab，而是：
  · 保留现有 dsh-editor（它已经能跑通、且和 ComfyUI 打通）
  · ArtCraft 作为「时间轴组件」嵌进粗剪 tab 的下半部分
  · 用 adapter 接缝把我们已有的素材库 / 导出链路接进去
```

理由：ArtCraft 的编辑器是一个**完整应用**（12 个 manager、53 个 command），
它的项目模型是 `TProject{scenes[]}`，我们的是平铺 tracks。
**整体替换意味着重写我们的数据层**；嵌时间轴只换 UI 层。

## 九、第 1 期第一道门槛：DSH IIFE 体系 —— ✅ 已通过（2026-10-20）

**问题**：第 0 期用的是独立 `<script src>`。DSH 插件包必须是
`window.__ModuleLoader__.load({ id, factory: (require) => {...} })`。
这道门槛不过，后面全不用谈。

**结论**：**通过。** 实测数据：

```
loaded     = "artcraft-dsh-proof"    __ModuleLoader__.load 生效
factoryOk  = true                    factory 返回 { mount }
mounted    = true                    mount() 调用成功
errs       = 0                       零错误
```

界面完整渲染（Assets / 预览画布 / 时间轴 / 属性面板 / Export）。
截图：`docs\evidence\ArtCraft-IIFE带样式-20261020.png`

### 三个必须知道的坑

#### ① `format:"iife"` + `globalName` 拿不到导出

```js
// esbuild 产物形态
var ArtCraftDshModule = (() => { ... return {mount} })();
// ↑ var 声明，在函数体内是局部变量，不会挂到 globalThis
```
报错：`Cannot read properties of undefined (reading 'mount')`

**修法**：用 `format: "cjs"`。产物是 `module.exports = {mount}`，
正好接上外层已有的 `var module = {exports:{}}`。
这也是 DSH 官方 `client.js` 的实际形态。

#### ② `external: ["react"]` 会把 `react/jsx-runtime` 一起排掉

esbuild 把 `react/jsx-runtime` 当成 `react` 的子路径。
产物里仍有 `require("react/jsx-runtime")`，而 UMD 的 React 没有这个入口
⇒ `React error #130`（Element type is invalid）。

**修法**：用 `alias` 把 `react/jsx-runtime` 指向 react 包内的真实文件，
让它打包进来。它只是 `createElement` 的语法糖，**不会产生第二个 React 实例**。
```
alias: {
  "react/jsx-runtime": path.join(HERE, "node_modules/react/jsx-runtime.js"),
}
```

#### ③ 判断「哪里坏了」必须用 dev 版 React

生产版只给 `Minified React error #130`，完全看不出是哪个组件。
换成 `react.development.js` 才看到真实信息：
```
Check the render method of `ForwardRef(ContextMenuTrigger)` and `SelectProvider`
```
**没有这一步，我会一直误判成「React 版本冲突」。**
