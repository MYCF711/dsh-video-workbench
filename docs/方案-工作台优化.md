## 一 · 目标与非目标

### 目标（本批）

```
① 产物带来源（一采 / 二采 / 高清重绘 / SeedVR2），来源由 bind.outputs 得出，不靠猜文件名
② 产物耐得住：关掉 ComfyUI 也能看（转存）

⑤ 提示词 + 当时的参数能存能套回
⑥ 成片能出字幕
⑦ 接不接得上是算出来的，不是看出来的

✗ 画质参数调优          → 等 §八 Q1（诊断未产出），届时以 M0 插队

## 二 · 模块划分

> 判据（`planning-draft` §5.4，三条全过）：
> ① 单模块可独立测试 ② 单模块可单独卸载（摘掉它，别人仍能跑） ③ 改动不波及别处

| # | 模块 | 职责（一句话） | 落在哪个包 | 依赖谁 | 可独立验收？ |
|---|---|---|---|---|---|
| **M1** | 产物来源 | 让每个产物知道自己是谁（`source` 字段） | `dsh-comfy-bridge` | 无 | ✅ curl 一趟看全 |
| **M2** | 产物转存 | 把产物从 ComfyUI 目录搬进自己的目录（含 temp） | `dsh-comfy-bridge` | M1 | ✅ 关掉 8188 后文件仍可读 |
| **M3** | 段间转场 | 相邻两段之间加 xfade，音画同步 | `dsh-editor` | 无 | ✅ 拼两段量时长 |
| **M4** | 草稿态协同 | 人只给意图、Agent 只补提示词、谁填的看得见 | `dsh-editor` | 无 | ✅ 空 prompt 加 3 段再精修 |
| **M5** | 提示词 Recipe | 提示词 + 当时的参数一起存，一键套回 | `dsh-editor` | 无 | ✅ 存一条再套回、逐项比对 |
| **M6** | 字幕 | 从成片音轨出 SRT 并烧入 | `dsh-editor` | 无 | ✅ 给 yz-result.mp4 出字幕 |
| **M7** | 衔接质检 | 算「这两段接不接得上」，含阈值标定 | `dsh-editor` | 无 | ✅ 先标定得分布，再判 4 段 |
| **M0** | 画质调参 | 按诊断结论调 bind 参数 | `dsh-comfy-bridge` | **§八 Q1（诊断）** | ⏸ 插队，不排进固定序 |

### 为什么这样切（每条都对着一个曾经想错的切法）

| 曾经的切法 | 为什么错 | 现在的切法 |
|---|---|---|
| ~~产物墙独立成包 `dsh-comfy-gallery`~~ | 摘掉它，工作台只剩空成果区 —— **功能上不独立**，只是技术上独立 | 画布已在 `canvas-room` 的包内，M1 只供数据 |
| ~~M1 拆成「元数据」+「同源代理」两个模块~~ | 两者同包，拆开后「元数据」交付时主人**看不到任何东西** | 合并；且同源代理**已交付**，M1 只剩元数据 |
| ~~指纹与 Recipe 合并实现~~ | 指纹在内存 Map（重启即丢），Recipe 要跨会话复用 | **解耦**：Recipe 从 `clip.shot` 取（已落盘），见 §五之四 |

### 三条判据自检

| 模块 | ① 独立测试 | ② 单独卸载 | ③ 改动不波及 |
|---|---|---|---|
| M1 | `curl /job/:id` 直接看到 `source` | 去掉字段，前端退回文件名规则（`RULES` 还在），一切照跑 | 只**加**字段；`modes()` 契约不动 |
| M2 | 生成 → 断 8188 → 直接打开文件 | `copyOutputs: false` 退回引用原 URL | 只加复制步骤，产物语义不变 |
| M3 | 两段拼片，`ffprobe` 量时长 | `transition: "none"` 退回硬切 | 只改 `render.mjs` 一条分支 + 一处断言 |
| M4 | 空 prompt 加 3 段 → 精修 | 闸门恢复「必须有 prompt」 | 放宽 schema + 加一个工具，不动 store |
| M5 | 存 → 清空 → 套回，逐项相等 | 删 `prompts.json` 即无 Recipe | 独立文件 + 3 工具，不碰 timeline store |
| M6 | 对比有/无字幕两版 | 不调就不跑 | 新增 `subtitle.mjs` + 1 工具 |
| M7 | 先标定得分布，再判 4 段 | 不调就不跑 | 新增 1 模块 + 1 工具，与 `audit_audio` 同构 |

## 三 · 实施顺序

```
M1 ─验收─→ M2 ─验收─→ M3 ─验收─→ M4 ─验收─→ M5 ─验收─→ M6 ─验收─→ M7
                                                         ↑
                                    M0（画质）诊断一到就插到【当前未开工模块】之前
```

### 为什么是这个顺序

```
M1 第一  —— 它是根。产物缺元数据是四类痛点的共同上游（草稿 E4/E5/E8/E9）。
            而且它已在做（lead 亲自动手），是当前唯一在跑的开发线。
M2 第二  —— 一采（202）实测就是 type=temp（E8/E9），ComfyUI 清理后随时 404。
            这是「可用但不耐久」→「可用且耐久」的那一步。
M3 第三  —— E12（render.mjs 291 行、xfade 命中 0）+ E13（transition -1..57 实测存在）
            ⇒ 全清单唯一「能力实测在、代码实测缺、只改一个文件」。投入产出比最高。
            它排在 M2 后，只因 M1/M2 是主人第一痛点（产物），M3 是第二痛点（观感）。
M4 第四  —— 「协同」两个字的落地形态。排在 M3 后，因为「看得见」优先于「流程」。
M5 第五  —— 没有它，M0 调好的参数会逐批丢失。**必须早于 M0**。
M6 第六  —— 字幕缺口 100%，但属于成片阶段，不急在预览阶段。
M7 第七  —— 标定需要「带转场」的样本 ⇒ 必须在 M3 之后。
M0 插队  —— 主人第一个痛点是「画面很脏」。诊断一到立刻插上，不因排队而等。
```

### 唯一的硬约束

```
M1 → M2 必须同一执行者、串行。
理由：两者都在 dsh-comfy-bridge 包内；AGENTS.md §3.12 记过「两个执行者改同一文件」
      的实测事故（后写覆盖先写，且互相以为对方改错了）。

M3–M7 全在 dsh-editor 包内，同样适用：一次只开一个，做完再开下一个。
```

## 四 · 每个模块的边界与接缝

### M1 · 产物来源

```
输入：bind.outputs 的 {语义key: 节点id}（实测：krea2 4 个 / yz·qwen21·qwen21-edit 各 1 个）
      来自 comfy.history() 的产物数组
输出：每个产物多一个字段
        source: "image" | "imageTwoPass" | "imageUsd" | "imageSeedvr" | null
        （null 表示「不在 bind.outputs 里」—— 实测抓到过 node 175 的附带 JPG）

与谁说话：
  ← comfy.history(promptId)            【不改它，它保持 ComfyUI 原样客户端】
  ← modeById.get(job.modeId).outputs   【bind.outputs，已在 workflows.mjs:287 收着】
  → 前端 AssetCanvas.classify()        【契约：优先读 o.source，null 时才走文件名兜底】

实现位置（★ 关键 —— comfy.mjs 拿不到 bind）：
  workflows.mjs  加纯函数 mapOutputSources(outMap, outputs)   ← 无 IO，可单测
  index.js       在 handlers.job() 里调用它，替换 outputs 字段
  comfy.mjs      **一行不改** —— createComfy({base}) 只收 base，history() 只收 promptId，
                 两个都拿不到 bind。映射是业务层的事。

卸掉它会影响谁：
  前端退回文件名规则（RULES 仍在），角标可能错位但不崩。
  M2 转存要用同一张表 → 会有第二处引用（这是重复的必要代价，见 §五之四）。
```

**验收**（每条都要真跑，写「未验证」的不算）：
```
□ curl /comfy-bridge/job/<id> → outputs 每一项都有 source 字段（存在性，不是 undefined）
□ krea2 四产物全开 → source 依次为 image / imageTwoPass / imageUsd / imageSeedvr
□ 表外节点（实测 node 175 的附带 JPG）→ source === null，且 JSON 里字段【存在】
   （负向：JSON.stringify({source: undefined}) 会丢掉字段，前端判 null 会写错）
□ yz / qwen21 / qwen21-edit → 各 1 个 source（video / image / image），不报错
□ 旧断言不回红：verify-m1.mjs、verify-m1-http.mjs 全过
   （断言写成 ≥N，不写死数量 —— AGENTS.md §3.7）
□ 前端 classify() 接上后，故意把 krea2 的 filename_prefix 改成 krea2-XXX
   → 角标【仍然正确】（这是本模块存在的唯一理由，必须验）
```

### M2 · 产物转存

```
输入：generate 完成后的产物列表（带 source）
输出：复制进项目 outputs/（按日期分目录）+ 新引用 URL
接缝：只加复制步骤；用 M1 的 mapOutputSources 那张表决定落哪个子目录
卸掉它：config.copyOutputs = false → 退回引用 ComfyUI 原 URL，其它一切照跑
```

**验收**：
```
□ 生成一次 → 四个产物全部在项目 outputs 下，字节数与源相等
□ 一采（type=temp 那个）也被转存 —— 实测 temp 目录最新一张 2,031,707 字节可经代理取到
□ 手写 <img src="转存后的文件">，直接打开 → 能看到图（不经过任何前端状态）
   ★ 不写「关掉 8188 刷新页面仍能看到」—— 草稿 E27 已证伪：
     WorkbenchView.js:605 的 job 是 useState(null)，刷新后前端没有 job 对象。
     转存负责的是「耐久的文件」，不是「耐久的界面状态」。
□ 重名不覆盖：同一天二次生成，文件名带序号或 hash
□ copyOutputs: false 时行为与改动前完全一致
□ 磁盘 delta 与实测 **13,651 KB（≈13.3 MB）** 同量级（±30%）
   ★ 数出来的：temp 一采 1,601 KB + 2ST 2,486 KB + USD 5,641 KB + SVR 3,923 KB
     （各取 output/temp 目录现有 15/9 个文件的算术平均，不是拿最大值拼的）
```

```
输入：render.mjs 的段列表 + 每段的 transition（默认 dissolve 0.3s）
输出：一条含 xfade 链的 filtergraph + 同步修正的 expectedDuration
接缝：只改 render.mjs；buildRenderCommand 的签名不变，只多读一个可选字段

```

**验收**：
```
□ 两段各 5s、转场 0.3s → ffprobe 实测时长 ≈ 9.7s（不是 10s）
□ expectedDuration 断言同步更新，且【故意传错】能被抓到（负向验证）
□ 音频同步 acrossfade，接缝处音画不错位（抽帧 + 波形对齐）
□ transition: "none" 时与改动前完全一致（verify-m7-render.mjs 全过）
□ 段数 = 1 → 不加转场、不报错
□ 段时长 < 转场时长 → 明确报错（不许静默产出 —— 工作站 AGENTS.md §3.4 陷阱）

**验收**：
```
□ 诊断结论里点名的每一个参数，都能在本次改动里找到对应改动点（不多改）
□ 改前用同一 seed 出一组、改后再出一组，四产物齐全
□ 新旧两组并排可比较（这是唯一能证明「变好了」的方式）
□ 四个产物仍然全部出得来（不许出现「改好了但少了一张」）
□ 现有四产物模板的参数可比性说明写进 docs（哪一批和哪一批能比）
```
