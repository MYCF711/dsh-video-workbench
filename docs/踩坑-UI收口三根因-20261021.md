# 踩坑 · UI 收口发现的三个根因（2026-10-21）

> 全部是浏览器实测 + 源码对照，不是猜的。
> 这三条解释了「为什么时间轴看起来不像 DSH 原生」，之前的文档都没写到根上。

---

## 一 · ★ 最严重：13 个语义色类在 CSS 里根本不存在

### 现象

时间轴的按钮、选中态、时间码，**全部是 `rgb(107, 107, 107)` 的灰**。
而 ArtCraft 自己的主题色 `--primary` 是 `216 100% 59%`（蓝）。

### 判据（三条，缺一不可）

```
① 裸 <button> 的浏览器 UA 默认底色 = rgb(107, 107, 107)   ← 完全一致
② #artcraft-tab-css 里只定义了 24 个 bg-*，全是 ui-* / white/black 系列
   零个 bg-primary / bg-secondary / bg-accent / bg-background / bg-border
③ 页面上 13 个语义色类被使用，全部「无定义」：
   bg-primary ×4   bg-accent ×5   bg-secondary ×3   bg-border ×4
   bg-background ×12   text-primary ×1
   bg-foreground/5 · /15 · /80
   border-border ×3   border-primary/50 ×2
   border-muted/50   border-foreground/10   border-muted-foreground/25 ×39
```

### 根因

`build-css.mjs` 里 Tailwind 的内容扫描没覆盖到这些类，或 `@theme` 的
`--color-primary` 没注册 ⇒ 工具类没被生成 ⇒ 元素回落到 UA 默认样式。

### 修法

在覆盖层里按 shadcn 约定补齐（`--primary` 是 HSL **分量**，必须 `hsl()` 包裹）：

```css
.ac-scope .bg-primary { background-color: hsl(var(--primary, 216 100% 59%)); }
```

### ★★ 教训（可推广）

**「元素有尺寸、位置对、文字对，但颜色不对」时，先查这个类在 CSS 里是否存在。**
不要先怀疑优先级 —— `rgb(107,107,107)` 这个值本身就是「UA 默认」的签名。
判据是：造一个裸 `<button>` 对比底色，一样就说明是 UA。

## 二 · 尺寸：`h-8/w-8` 压过 `size-7`

### 现象

工具条按钮实测 32px，DSH 原生是 28px。

### 根因

按钮同时带三个类：

```html
<button class="size-7 h-8 w-8">
```

而 ArtCraft CSS 里：

```css
.ac-scope .size-7 { width: 1.75rem; height: 1.75rem; }  /* 28px */
.ac-scope .h-8    { height: 2rem; }                       /* 32px，在后面 */
.ac-scope .w-8    { width: 2rem; }                        /* 32px，在后面 */
```

同特异性，**后出现的赢** ⇒ 32px。

### 修法

```css
.ac-scope .size-7.h-8.w-8 { height: 1.75rem; width: 1.75rem; }  /* 0,3,0 赢过 0,2,0 */
```

### ★ 教训

Tailwind 的 `size-N` 和 `h-N/w-N` 同时出现是**矛盾声明**，
不是「后写的覆盖前面」那么简单 —— 取决于生成顺序。
量尺寸时看到「比预期大 4px」，先看元素上有没有成对的 `size-` 与 `h-/w-`。

## 三 · 标尺：`10f / 20f / 6f` 是上游合法设计，但永不落到整秒

### 现象

时间轴标尺显示 `00:00 / 10f / 20f / 6f / 16f / 2f / 12f / 22f / 8f / 18f`，
看起来像「按 +10 模 24 绕回」的 bug。

### 真相

`ruler-utils.ts:161-177` 逐字：

```ts
// Formats a ruler tick label:
//   - on second boundaries: "MM:SS" (or "H:MM:SS" past 1 hour)
//   - between seconds:     "Xf"    (frames within the current second)
```

⇒ **这是设计意图**，CapCut 同款。`10f` = 「第 0 秒内的第 10 帧」。

### 但有个真缺陷

```ts
const LABEL_FRAME_INTERVALS = [2, 3, 5, 10, 15] as const;
```

标签间隔按帧数取，但**只有 2 和 3 能整除 24fps**：

```
 2 帧 = 0.0833s   24/2  = 12   ✓ 落整秒
 3 帧 = 0.1250s   24/3  = 8    ✓ 落整秒
 5 帧 = 0.2083s   24/5  = 4.8  ✗ 永不落整秒
10 帧 = 0.4167s   24/10 = 2.4  ✗ 永不落整秒   ← 当前就是这个
15 帧 = 0.6250s   24/15 = 1.6  ✗ 永不落整秒
```

实测当前：标签间隔 155px，372px/秒 ⇒ 每个标签 0.4167 秒 = 10 帧。

⇒ **一旦缩放跨过 3 帧间隔，就再也看不到整秒刻度**，
用户看到的永远是一串帧号。这不是「显示 bug」，是「设计盲区」。

### 修法（按主人 2026-10-21 决策「刻度改成秒」）

把 `LABEL_FRAME_INTERVALS` 换成能整除 fps 的值，
或让 `formatRulerLabel` 在非秒边界也输出秒（如 `0.4s`）。

★ 需改上游 `ruler-utils.ts` 并重跑三步构建（约 3~5 分钟）。

## 四 · 顺带发现的两个小问题（已修）

### 4.1 UA 默认 button 边框

```
实测：时间码按钮 border = "2px outset rgb(255,255,255)"
      ⇒ 截图上表现为一个白框，很容易误认成「选中态」
根因：ArtCraft 的 CSS 没有全局重置 button 的 border
修法：.ac-scope button:not(.border):not(.border-border):not(.border-transparent) { border: 0; }
      ★ 不能写成 button { border: 0 } —— 会杀掉 7 个有意设了 border 的按钮
```

### 4.2 `--st-panel` 比 `--st-bg` 更暗，与 DSH 层级方向相反

```
ArtCraft : --st-bg #121316  >  --st-panel #101014     （panel 更暗）
DSH      : --dsw-alias-bg-base #151517  <  --dsw-alias-bg-layer-1 #232324  （layer 更亮）
```

⇒ **不能简单对等映射**。若照字面把 panel→bg-layer-1，会变成「面板比底色亮」，
观感与 ArtCraft 原设计相反。

本项目采用：`bg-background`（大面积底色）→ DSH bg-base，
`.panel`（卡片/分栏）→ DSH bg-layer-1。这是按**语义**映射，不是按名字。

## 五 · 排查过程中我自己踩的四个坑（方法学）

```
① 把缩放后的截图当成 1:1 —— 16px 图标在 1256/1912 缩放后像方块，
   我一度判「图标字体缺失」。实际 34 个 SVG 全在、path 全齐。
   判据：先读 getBoundingClientRect() 与 devicePixelRatio，再看截图。

② setAttribute('style', old + '...') 会覆盖 React 已写的 style，
   之后被 diff 还原 ⇒ 误判「改不动」。
   正解：style.setProperty(k, v, 'important')。

③ 先猜「@layer 优先级」浪费了三轮。真相是「类根本不存在」。
   教训：改不动时先问「这条规则存在吗」，再问「谁赢了」。
   判据：禁用所有样式表后值不变 ⇒ 不是 CSS 优先级问题。

④ 把 ::selection 高亮当成「元素有蓝底」。
   判据：getComputedStyle(el).backgroundColor 是 transparent 就不是它。
```
