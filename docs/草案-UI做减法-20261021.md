## 二 · 十条问题 → 具体修法

### ① 工程名输入框

```
现状：border 2px inset rgb(118,118,118)；padding 1px 8px
根因：Tailwind preflight 被关掉，input 吃到 UA 默认样式

改成（DSH 做法）：
  border: 0
  background: transparent
  padding: 0 8px
  height: 28px
  border-radius: 8px
  font-size: 13px
  color: var(--dsw-alias-label-primary)
  &:hover  { background: var(--dsw-alias-interactive-bg-hover) }
  &:focus  { background: var(--dsw-alias-bg-base);
             box-shadow: inset 0 0 0 1px var(--dsw-alias-state-business-primary) }
```

### ② 导出面板浮层

```
现状：w=336  right=1912（零留白）  radius=0  shadow=none  bg=transparent
根因：那一层只是定位容器，没浮层外观；mr-4 被 Radix popper 覆盖

改成：
  width: 320px
  margin: 8px                      ← 四周留白，永不贴边
  max-height: min(70vh, 560px)
  background: var(--dsw-menu-surface-fill)
  backdrop-filter: blur(40px) saturate(150%)
  border-radius: var(--dsw-radius-lg, 16px)
  box-shadow: var(--dsw-elevation-prominent)
  padding: 8px

  行规格：
    行高 32px（不是现在的 45px —— 现在太散）
    标签 13px label-secondary
    值   13px label-primary
    hover 整行 rgba(0,0,0,0.04) 圆角 8px
```

**同时修掉**：格式那行现在有个蓝色聚焦框 —— 那是 `<select>` 的原生焦点样式，
换成 DSH 的「整行 hover，点击才展开」。

### ③ 素材面板

```
现状：scrollWidth 280 / clientWidth 264，溢出 16px，出横向滑块

改为【一列】：
  容器 width: 100%，box-sizing: border-box
  卡片 min-width: 0（让 flex 子项能收缩）
  所有内部元素用 % 而不是固定 px
  overflow-x: hidden（一列本来就不该横滚）

  空态（拖拽区）：
    居中，图标 48px，文字 13px label-tertiary
    高度占满，上下留白对称
```

**为什么不双列**：可用宽 264px，双列每卡 126px，缩略图看不清。
主人自己图里也是单列大卡。

### ④ 轨道盖住 DSH 侧栏手柄（这条最隐蔽）

**实测链条**：
```
DSH viewArea:        x=280  w=1625  →  右边界 1905
DSH 列宽手柄:        x=612  w=10    z-index 0
ArtCraft 时间轴 section: x=292  w=1601  position:relative
```

**根因**：ArtCraft 的整个 `.ac-scope` 铺满 viewArea 全宽（1625px），
它内部的 section 有 `position: relative` + 自己的背景色，
**视觉和事件层都盖在 DSH 的 x=612 手柄上面**。

⇒ 主人在轨道区拖拽时命中 DSH 手柄 ⇒ 看起来像「轨道能拖 DSH 侧栏」。

**这不是 CSS 能安全修的**（给 DSH 手柄加 pointer-events:none 会破坏 DSH 自己）。
必须查：**为什么 ArtCraft 会跨过 DSH 的 panel 边界？**

**待查项**（这条需要实装前先定位）：
```
· viewArea 里除了 ArtCraft 还有别的 panel 吗？
· 那个 x=612 的手柄属于哪个 panel 组？
· 如果 DSH 的 panel 组本身就在 viewArea 内部，那 ArtCraft 就不该铺到 1905
```

### ⑤ 音轨拖不回 + 幽灵「音频」轨

**两个独立缺陷**

```
缺陷 A：拖不回
  resolveTrackPlacement 的 explicit 模式在目标区间重叠时静默返回 null
  → insertElement 什么都不做，用户看不出发生了什么
  修：explicit 失败时必须报错（toast 或控制台 + 视觉反馈）

缺陷 B：幽灵轨
  拖放时 trackId 解析失败 → 走 auto 分支
  → auto + firstAvailable 装不下 → 新建轨，名字用 DEFAULT_TRACK_NAMES.audio
  → 就是那条「音频」
  修：音频/视频轨全满时【不新建】，直接报「没有空位」
     因为主人的四轨布局是固定的设计，不是「轨道越多越好」
```

### ⑦ 工具栏从 17 个 → 8 个常驻

**分三档**（依据：图标本身是否够直观 + 使用频率）


### ⑧ @卡片定位 + tag 菜单白字

```
定位（根因：按字符数估算，不是真实宽度）
  改用 Range API 拿真实像素：
    const range = document.createRange();
    range.setStart(textNode, caretIndex);
    range.collapse(true);
    const rect = range.getBoundingClientRect();
    → chipCandidate.left = rect.left
  这样文字一变位置立刻跟上。

tag 菜单配色（根因：用了 label-primary-foreground，白底白字）
  文字：var(--dsw-alias-label-primary)        ← 不是 foreground
  背景：var(--dsw-menu-surface-fill) + blur
  选中项：左侧 2px 品牌色条 + 文字保持 primary
```

### ⑩ 做减法的三条具体规则

```
规则 1  一个控件只有一个功能入口
        （不要"图标 + 下拉 + 快捷菜单"三套并存）

规则 2  能用文字就不用图标，能用图标就不用下拉
        （文字最省认知，下拉最费）

规则 3  任何"摘要/预览/提示"行，如果信息在别处已有，删掉
        （本镜配方就是这条的反例）
```
