## 一 · 上传本地视频失败（主人：「这两个还是导入不了本地的视频」）

### 根因：协议不匹配，两端各自都正确

```
客户端 dsh-artcraft-tab/src/adapters.js:uploadLocalFile
  发 multipart/form-data：
    const fd = new FormData(); fd.append("file", file);
    fetch("/comfy-assets/upload", { body: fd })

服务端 dsh-comfy-workbench-tab/lib/index.js:1288-1304
  只接受 JSON：
    body = JSON.parse(Buffer.concat(chunks).toString("utf8") || "{}")
    catch { return json(res, 400, { error: "请求体不是合法 JSON" }) }
    const filename = String(body.filename ?? "").trim();
    const base64 = String(body.base64 ?? "");
```

⇒ FormData 被当成「不合法 JSON」打回 400。

### 实测对照（同一个 1×1 PNG）

```
multipart/form-data  → 400 {"error":"请求体不是合法 JSON"}
application/json     → 200 {"ok":true,"id":"input:wb_verify-upload_xxx.png"}
```

### 第二个坑：响应是扁平结构

```
真实响应：
  {"ok":true,
   "id":"input:wb_probe-json_fqdlbr.png",
   "absPath":"D:\\Comfy-Desktop\\ComfyUI-Shared\\input\\wb_probe-json_fqdlbr.png",
   "filename":"wb_probe-json_fqdlbr.png",
   "sizeBytes":70,
   "displayName":null}
⇒ id 在【顶层】，没有嵌套的 item。
  第一版按 j.item.id 取，会报「上传成功但没返回资产 id」。
★ 教训：协议对齐不能只看「字段名叫什么」，要打一次真实请求看响应长什么样。
```

### 修法

改客户端（不动已验收的后端，因为它还负责 64MB 上限 / 扩展名白名单 / 不覆盖既有文件）：

```
· File → base64（分块 btoa，避免大文件栈溢出）
· 发 { filename, base64 } + Content-Type: application/json
· 按扁平结构取 j.id
· 加 48MB 预检（base64 膨胀 1/3，服务端上限 64MB）
```

### 同一错误在两处

```
dsh-artcraft-tab/src/adapters.js              ← 实际生效（已修）
dsh-comfy-workbench-tab/src/artcraft-wire.mjs ← 死代码（没被构建进 lib/index.js，也已同步修）
★ 本项目老坑 §6.43：一个字段有 N 条构造路径，只修一处 = 没修。
```

### 验收

`packages/dsh-artcraft-tab/verify-upload-protocol.mjs` **16/16**

## 二 · 工程菜单粗糙 + Shortcuts 英文（主人：「这一个位置还是也能粗糙」）

### 修前

```
工程菜单触发按钮 = 一个 20×20 的纯色方块（bg-foreground/80）+ rounded-sm(2px)
  · 没有任何图形语义，看不出这是「工程菜单」
  · 圆角 2px 不在 DSH 圆角阶（4/8/12/16）
  · size-8(32px) 比 DSH 工具条按钮（28px）大一圈
菜单项「Shortcuts」= 整个菜单里唯一残留的英文
```

### 修后

```
按钮 → Menu01Icon 图标 + 28×28 + 圆角 8px
菜单项 → 「快捷键」
菜单宽度 → w-44 → w-48（给「快捷键 + 图标」留够）
```

### 踩到的坑

```
❌ 只改了 JSX 用了 Menu01Icon，忘了改 import 那行
   ⇒ 运行时报 "Menu01Icon is not defined"
   ⇒ esbuild 不做未定义变量检查，构建能过、运行时才炸
   ★ 判据：改 JSX 用了新图标，必须同步查 import 那一行。
```

### 实测

```
工程菜单按钮：28×28 BUTTON，aria-label="工程菜单" ✓
菜单内容：「退出工程 | 快捷键」全中文 ✓
浮层底色：rgba(248,249,250,.58) = DSH 浅色毛玻璃 ✓
浮层圆角：16px ✓
```

## 三 · 命名区粗糙（主人：「然后命名那里也很粗糙的ui」）

### 修前

```
一个裸 <input type=text> 当显示用：
  · 圆角 rounded-sm = 2px（不在 DSH 圆角阶）
  · 高度 h-8 = 32px（比工具条按钮 28px 高一档）
  · 字号 text-[0.9rem] = 14.4px（DSH 正文是 13px）
  · hover 同时改底色和文字色（hover:text-accent-foreground）—— 暗色下会闪
  · 宽度靠 fieldSizing:content，无上限 ⇒ 长名字把右侧「导出」顶出去
```

### 修后

```
h-7(28px) / 13px / 圆角 8px / hover 只改底色 / max-w 256px / 焦点环用 box-shadow
```

### 两个坑（都是「看起来改了，其实没生效」）

```
❌ 坑① 我自己写的对齐层把它压回去了
   dsh-native.css.js 里有一条：
     .ac-scope input:not([type="radio"]):not([type="range"]) { border-radius: 0.25rem }
   特异性 (0,3,0)，而我给命名框写的 .ac-scope header input[type="text"] 只有 (0,2,1)
   ⇒ 圆角被强制成 4px，改了等于没改。
   修：把 input 从那条通配规则里摘出来（多行输入框/搜索框/命名框各有各的圆角），
       并给命名框那条加 !important。

❌ 坑② max-w-[16rem] 这个 Tailwind 任意值类没被生成
   computed maxWidth = none。
   原因：ArtCraft 的 build-css 内容扫描没覆盖到 editor-header.tsx 的这一处。
   修：在覆盖层里显式写 max-width: 16rem，不依赖任意值类生成。
```

### 实测

```
h: 28px ✓   radius: 8px ✓   maxWidth: 256px ✓   无报错 ✓
```
