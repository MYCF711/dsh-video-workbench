## 0.5 · 结论先放前面

后三张「脏」不是同一个病，是**三个各自独立的机制**。按严重程度：

| 张 | 病灶 | 元凶（节点/参数） | 证据强度 |
|---|---|---|---|
| 第3张 | **满脸斑点（雀斑状细碎色块）** | `191 UpscaleModelLoader: OmniSR_X4_DIV2K` + `194 PrimitiveFloat: 1.5` —— 拿 ×4 模型干 ×1.5 的活 | 代码逐字坐实配置矛盾；像素统计+肉眼坐实结果 |
| 第4、5张 | **发闷发灰 + 扎眼** | `195.image`/`900.image` 接 `208`（一采草稿）而非 `223`（二采成品）；再叠 `173 ImageSmartSharpen+ sharpen=5` | 算术+互相关+肉眼，三重坐实 |
| 全部后三张 | 整体偏暗偏闷 | 链路上游的暗调累积（见 §3.5） | 统计量坐实，归因未逐段闭环 |

**最重要的一条**：第4、5张**根本不是主人夸的那张图的下游**。

```
node 195 JoinImageWithAlpha .image  ←  ["208", 0]   ← 一采 VAEDecode（1368×768）
                                    应该是 ["223", 0]  ← 二采 VAEDecode（2048×1152）
```

两条硬证据：
1. **尺寸算术**：第4张 = 2052×1152，而 `1368×1.5=2052`、`768×1.5=1152`（node 183 的 ×1.5）。第1张恰是 1368×768。若来自第2张（2048×1152），×1.5 应是 **3072×1728 —— 那正是第3张的尺寸**。两条链分得干干净净。
2. **内容对不上**：灰度归一化互相关 `第2 vs 第4 = 0.7709`，而 `第2 vs 第3 = 1.0000`、`第4 vs 第5 = 1.0000`。100% 放大看，第2张有麻花辫和带深色条纹的毛衣，第4张这两样都没有（`画质对比-20261018-内容分歧.png`）。

## 3 · 罪魁排序

### 🥇 第3张：`OmniSR_X4_DIV2K` 被用来做 1.5 倍放大

代码逐字（`custom_nodes\ComfyUI_UltimateSDUpscale\repositories\ultimate_sd_upscale\scripts\ultimate-upscale.py` L28）：

```python
self.scale_factor = math.ceil(max(p.width, p.height) / max(image.width, image.height))
```

代入这批的实际数字（输入 2048×1152 → 目标 3072×1728）：

```
scale_factor = ceil(3072 / 2048) = ceil(1.500) = 2
get_factors(2) → [2]        （get_factor: num%4→4, num%3→3, num%2→2, 其余0）
```

`scale_factor=2` 而 `OmniSR_X4_DIV2K` 是**固定 ×4** 的放大模型。`upscaler.py` 走 `ImageUpscaleWithModel.execute(...)`，那是按**模型自身倍数**放大的，不认 `scale` 参数 —— 于是：

```
2048×1152  ──OmniSR_X4──►  8192×4608   （真的做了 ×4 推理，细节/伪影一起放大 4 倍）
           ──LANCZOS──►    3072×1728   （再 ÷2.67 缩回）
```

**这是在拿 4 倍模型干 1.5 倍的活：中间多了一次 ×4 的生造细节，然后被 ÷2.67 揉碎。** 那些被 OMniSR 无中生有出来的高频，缩小时不会消失，只会被压成**固定尺度的斑点**——正好对上第3张满脸色斑的样子。

**证据**：
- 配置矛盾由**代码逐字**坐实（L28 + `get_factor` + `upscaler.py`），不是推测。
- 结果由**像素统计 + 肉眼**坐实：同尺寸平坦区颗粒第3张最高（0.00371 vs 第2张 0.00329）；`画质对比-20261018-第3张面部.png` 里，第2张脸颊是干净渐变，第3张是均匀铺满的雀斑状纹理，连下颌、额角、嘴唇周围都有 —— 真实皮肤不会这样均匀地长。
- **反证**：纯 LANCZOS 做 ×4 再 ÷2.67 的往返，实测 HF 0.00825 / grain 0.00175，与直接 ×1.5（0.00821 / 0.00178）几乎无差 —— **纯重采样不会生斑点**。斑点只能来自模型推理。
- **边界（如实说明）**：OmniSR 模型的推理无法离线复现（要 GPU 加载模型），所以"斑点 = OmniSR ×4 的产物"是**由配置矛盾 + 采样统计 + 反证共同支持的强推断**，不是我把模型跑了一遍得到的直读。

#### 罪魁二：`node 173 ImageSmartSharpen+` 锐化过头

**参数：`sharpen=5`、`ratio=0.5`、`noise_radius=7`、`preserve_edges=0.75`**

**(a) 读源码弄清真实数学。**
`custom_nodes\ComfyUI_essentials\image.py`：
```python
img = ratio * sharpened + (1 - ratio) * blurred
```
`sharpened` 来自 `kornia.enhance.sharpness(img, sharpen)`。kornia（`kornia/enhance/adjust.py`）是**固定核 + 外推**：
```
核 = [[1,1,1],[1,5,1],[1,1,1]] / 13          ← 不随 factor 变
res = blur13 + factor * (img - blur13)      ← _blend_one；factor>1 只做 0/1 裁剪
```
所以 **`sharpen=5` = 从自己的 13 抽模糊里向外推 5 倍**，等效 `5·img − 4·blur13`，必产生过冲。
而 `blurred` 那一路是 bilateral，`preserve_edges=0.75` 被翻译成 `sigma_color = 1−0.75 = 0.25`（几乎不过滤）——实测只掉 14% 高频。所以 `1−ratio=0.5` 这个"柔化"一半**基本没起作用**：一半强度白扔，过冲全留下。

**(b) 用 ComfyUI 自己的 venv + 原版节点代码离线回放，扫参数**（输入 = 第2张 ×1.5 到 2052×1152）：

| node173 参数 | HF | 相对输入 |
|---|---|---|
| `sharpen=1.0, ratio=1.0` | 0.01295 | **1.00×（精确恒等）** |
| `sharpen=1.5, ratio=1.0` | 0.01511 | 1.17× |
| `sharpen=2.0, ratio=1.0` | 0.01733 | 1.34× |
| `sharpen=2.5, ratio=1.0` | 0.01958 | 1.51× |
| **`sharpen=5.0, ratio=0.5`（现网）** | **0.01955** | **1.51×** |
| `sharpen=5.0, ratio=0.3` | 0.01552 | 1.20× |
| `sharpen=5.0, ratio=1.0` | 0.03032 | 2.34× |

两条结论：
- **现网 `5/0.5` 的实际强度 = `sharpen=2.5` 单打独斗。** `ratio=0.5` 让写着的 5 只兑现一半，但过冲是满的。

#### 罪魁三：`node 184` 的 `adain` 与整体偏暗

节点自带文档逐字（`comfy_extras\nodes_seedvr.py`）：
```
lab:     transfer color in CIELAB space, preserving detail (most faithful)
wavelet: transfer low-frequency color, keeping upscaled high-frequency detail
adain:   match per-channel mean/std (fastest, global tint)      ← 现网

```
`adain` 是作者标注的**最粗、最快**那档，只做逐通道 mean/std 对齐、不分区。tiled 解码下会放大块间色偏 —— 第4张分块 CV 0.540 vs 第2张 0.365。

**但它不是"变暗"的主因**：把第4张逐通道 mean/std 对齐到第2张后再测，HF 0.02828 → 0.02982（**不降反升**）。说明第4张的脏主要来自**纹理**，偏暗另有来源。

### 3.5 整体偏暗（后三张共有）—— 归因只做了部分闭环

后三张的亮度 L 均值：第2张 **26.48**、第3张 24.12、第4/5张 **22.08**。这个影响不可忽略：色偏 ΔE 9.35 里很大一部分是**明度差**（ΔL≈4.4），体感就是"发闷、发灰"。

**我做到的**：确认了它不是 `adain` 或 JPG 造成的（对齐调性后纹理差反而变大；JPG 往返 39.93 dB）。
**我没做到的**：逐段闭环定位是哪一步把亮度压下去的（四个候选：SeedVR2 单步重建的 VAE 往返、`adain` 的 std 匹配、一采→二采→放大链上累积的暗调、以及一采本身就更暗）。这需要能提交受控任务才能定位。

### 改 A（治第3张，收益最大）：换掉 ×4 模型 / 别让它干 ×1.5 的活

**三个方案，按推荐度：**

**A1（推荐）：把 `upscale_model` 换成真正的 2 倍模型**
```
节点：191  UpscaleModelLoader
参数：model_name: "OmniSR_X4_DIV2K.safetensors"  →  "OmniSR_X2_DIV2K.safetensors"（若本机有）
```
- **预期效果**：`scale_factor=2`、`get_factors(2)→[2]` 与 2 倍模型**对齐**，不再有 ×4→÷2.67 的揉碎。斑点应消失。
- **风险**：需先确认本机有 X2 模型（我没有验证本机 upsacle_models 目录里有什么，**这条要落地前先 `Get-ChildItem models\upscale_models`**）。若没有，转 A2/A3。

**A2：把 `upscale_by` 调成 2.0，让目标尺寸匹配模型的 ×4**

```
节点：194  PrimitiveFloat (放大倍数)
参数：value: 1.5  → 1.0
节点：192  PrimitiveFloat (边分块数)  —— 影响 tile 尺寸，见下
```
说明：`scale_factor = ceil(target/max(输入))`；要让 `get_factor` 走出 4，需要 `scale_factor` 是 4 的倍数。若 `upscale_by=1.0`，`ceil(2048/2048)=1` → `get_factor(1)=2` → 仍是 2。这条路要凑到 ×4 需要 `upscale_by ≥ 4`，输出 8192×4608 —— **不现实**。所以 A2 实际不可行，仅列出以说明"调倍数凑模型"这条路走不通。

**A3（最稳、零新依赖）：把 `upscale_model` 设为 None，只用 LANCZOS 放大**
```
节点：199  UltimateSDUpscale
参数：upscale_model → (None)
```
- **预期效果**：`upscaler.name == "None"` 时走 `self.image.resize((p.width, p.height), LANCZOS)` 直接到位，完全没有 ×4→缩回的环节。斑点必然消失（实测纯重采样往返不产生斑点）。
- **风险**：失去模型放大的细节增益，第3张会更"软"。但配合下面改 E 提高 denoise，细节由采样补而不是由放大模型硬造 —— 这本来是更干净的做法。

**A4（若想保留 OmniSR 的细节）：把目标尺寸改成 4 倍整数**
```
节点：194  PrimitiveFloat  value: 1.5 → 4.0
```
- **预期效果**：`ceil(8192/2048)=4` → `get_factor(4)=4` → 模型 ×4、目标 ×4，**完全对齐，中间无重采样**。这是唯一"用对" OmniSR_X4 的方式。
- **风险**：输出 8192×4608，显存与耗时大幅上升（RTX 5070 Ti 16GB，且 tile 数会从 8 涨到 32）。**不推荐默认开，但这是验证「斑点是否来自 ×4→缩回」的决定性实验** —— 如果 A4 下斑点消失，就闭环了 §3 的推断。

## 6 · 一页总结

> **先看 §0：改 B/C/D 已被另一支路落地并实测通过（第4张互相关 0.7709→0.9967，高频比 2.05→1.037）。第3张的斑点未修，改 A 是唯一剩下的活。**

**后三张「脏」是三个不同的病，不是一个参数的锅：**

**第3张（斑点）** —— `191 OmniSR_X4_DIV2K` 是 ×4 模型，而 `199` 的 `upscale_by=1.5` 经 `ultimate-upscale.py` L28 `ceil(3072/2048)=2` 后仍按 2 倍路径走，模型实际做了 2048→8192（×4）再 LANCZOS 缩回 3072（÷2.67）。**×4 生造的细节被揉成满脸斑点。** 纯重采样不会生斑点（往返测试几乎无差），所以斑点必来自模型。
→ 改：`191` 换 OmniSR_X2（若有），或把 `199.upscale_model` 设为 None 改用 LANCZOS，或 `194=4.0` 让目标与 ×4 对齐（决定性验证实验）。

**第4、5张（发闷+扎眼）** —— 两件事叠加：
1. **`195.image`/`900.image` 接 `208`（一采草稿）而非 `223`（二采成品）。** 主人夸的第2张从未进入这条链；互相关 0.7709、右下角内容肉眼完全不同。一采之所以和二采差这么多，是因为二采是 `denoise=0.5` 的大幅重绘。
2. **`173 ImageSmartSharpen+ sharpen=5, ratio=0.5`** —— 等效 `5·img−4·blur13` 向外推，把过冲/下冲放大到第2张的 **2.4 倍**，单独贡献 **+38%** 高频。
→ 改：`195.image`/`900.image` → `["223",0]`；`173` 改 `sharpen=1.0, ratio=1.0`（实测精确恒等）。

**后三张共同偏暗**（L 26.48 → 22~24，暗部占比 41.9% → 53.4%）—— 这条我**没有**逐段闭环归因，只确认了不是 `adain` 也不是 JPG 造成的。要定位得能提交受控任务。

**已排除**：tile 接缝（0.735–0.917）、重复放大（两条不同支路）、JPG q90（往返 39.93 dB）、`adain` 拉对比度（std 反而降）、水印（是暗部毛衣）。
**并修正了我自己的一个错误判断**：最初我把第3张判为"纯插值假高清"，被自己的往返测试推翻 —— 纯重采样不生斑点，它的病是 ×4 模型揉出来的。
